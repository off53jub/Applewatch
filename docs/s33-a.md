## 強7 TestFlight を 1 日 1 回に（`.github/workflows/testflight.yml`）

- `on`: `push: main` をやめ、`schedule`（毎晩 UTC 14:00＝日本時間 23:00・仮）。`pull_request`（組み立ての確かめ）と `workflow_dispatch`（手で動かすボタン）は残す
- `changes` の中の `due`: 夜の 1 回は、直前のアプリのリリース（タグが `v` で始まるもの。家の PC の `pc-v…` は見ない）の `target_commitish` が今の main と同じなら作らない（`TESTFLIGHT_RESULT: skipped reason=unchanged` の注記だけ）。調べられないときは作る側
- リリースに残すのは `pull_request` 以外の main（夜の 1 回と手で動かしたとき）。内部テストのグループへ渡すのも同じ（`asc.py` に `schedule` を足した）。届かなかったら赤にする条件にも `schedule`
- 「テストする内容」の頭に「この版で見る 3 つ」: 前の版のあと（無ければこの 24 時間）に main に入った PR の題から 3 つまで（新しく入った順・同じ題は 1 つ・CI・文書・家の PC だけらしい題は足りないときだけ）。PR が読めなければ前のまま（コミットの題の一覧）
- 確かめ: python で YAML を読めた（triggers が schedule・pull_request・workflow_dispatch）・`run` の段を全部 `bash -n` に通した・`test_ci_scripts.py` 16 本が通った
- 気づいたこと: PR の組み立ても、Secrets があれば TestFlight に上がる（テスターには渡らない）のは前のまま。数が多いのはこれも理由かもしれない（仮説・変えていない）
