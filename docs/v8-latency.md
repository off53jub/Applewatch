# 文字になるまでを短くする（2026-11-07）— iPhone と家の PC（版 8）の決まり

本人の願い: 「文字起こしを PC に送って文字にしたものが iPhone に入るまでの時間を短くしたい」。本人が選んだ6つ（全部）:

1. 区間ごとの時間を測って見せる
2. 送った返事で文字を返す（待ち合わせ）
3. 「できた」の見えない通知は、返事で返せなかったときの保険にする
4. 区切りを短くする（無音の所で区切り、長くても2分）
5. 下書きを先に出す（速いモデルの結果を「仮」として先に見せ、多数決の結果で差し替える）
6. 遅れているときは新しい区切りから文字にする

決まりの前提は docs/v7-plan.md と同じ（合言葉・日時は ISO 8601 の UTC ミリ秒つき・PC は受け取ったものを外に出さない）。
PC の版は 8（上げるのはつなぐ人）。`/hello` の features に、使えるとき `jobwait`・`draft`・`timing` を足す。iPhone は features を見て使う。

## 1. 時間を測る

- iPhone は `POST /jobs` の query に、分かるものを足す:
  `chunk_start`・`chunk_end`（区切りの録音の始まりと終わり）・`arrived`（iPhone に届いた時刻。iPhone で録ったものは区切りの終わりと同じ）・
  `sent`（送り始めた時刻）。
- PC は仕事ごとに `received`（受け終わり）・`started`（文字にし始め）・`draft_at`（下書きができた）・`finished`（でき上がり）を残し、
  `GET /jobs/<名前>` と待ち合わせの返事に `"timing": {...}` として、上の iPhone の時刻と合わせて返す。
- iPhone は記録に入れた時刻 `applied` を足して、区間ごとの秒数を出す:
  録音の終わり→iPhone（時計から届くまで）、iPhone→PC（送るまで）、PC の待ち（received→started）、PC の作業（started→finished）、
  PC→記録（finished→applied）、合計（chunk_end→applied）。
- iPhone は直近24時間の区間ごとの中央値と数を、自己点検に出し、`/diag` の `state.latency` で PC に送る:
  `{"count": 12, "toPhone": 40.5, "toPC": 3.2, "pcWait": 1.0, "pcWork": 25.4, "toRecord": 6.0, "total": 80.1}`（秒。分からない区間は省く）。
- PC は自分の分（待ち・作業）を見守りの画面に出し、iPhone から届いた latency も「実機の様子」と summary.md に出す。

## 2. 待ち合わせ — `POST /jobs?wait=1`

- iPhone は区切りを送るとき `wait=1` を付ける（features に `jobwait` があるときだけ）。
- PC は受け取ったら、文字にし終わるまで返事を待たせる。そのあいだ、つながりが切れないよう15秒ごとに空白を1文字書く
  （JSON の前の空白は読み飛ばされる）。でき上がったら、`GET /jobs/<名前>` と同じ形の答え（status・result・timing）を書いて閉じる。
  25分たってもできなければ `{"status":"pending", ...}` を返して閉じる（仕事は続ける）。
- 返事を書き終えた仕事は「iPhone に渡した」と覚える。渡せなかった（途中で切れた・待ち合わせでなかった）仕事だけ、
  でき上がりで「できた」の見えない通知（kind `job`）を送る（今の回数の上限はそのまま）。
- iPhone は、裏の送信（PCJobUploader の background URLSession）の返事の中身を受け取り、done なら答えを
  端末の中（Caches/pcresults/<名前>.json）に置いて、取り込み（processQueue）を進める。取り込みの「PC の仕事はできたか」は、
  先にこの置き場所を見る（あれば PC に聞かない）。送信の待ち時間の設定は、空白が届くかぎり切れないようにする（例: request 120 秒）。

## 5. 下書き

- PC は仕事を文字にするとき、先に速いモデル（haas・reazon）だけで文字にして「下書き」として残し、そのあと多数決をする。
  `GET /jobs/<名前>` は、まだのとき `{"status":"working","draft":{...result と同じ形...},"timing":{...}}` を返す。
- 待ち合わせ（wait=1）は、でき上がりまで待つ（下書きでは返さない）。
- iPhone は、アプリが前にあるとき（画面を見ているとき）だけ、送ってまだの仕事を15秒ごとに `GET /jobs/<名前>` で見て、
  下書きがあれば「今日」の画面と時計の「さっきの会話」に「仮」として出す。**下書きは記録には保存しない**（同期にも入れない）。
  でき上がりが記録に入ったら、その区切りの仮は消す。

## 6. 新しい区切りから

- PC は、まだ文字にしていない仕事が2つ以上あるとき、いちばん新しく受けたものから文字にする（古いものはあとで）。
  1つしかなければ今までどおり。

## 4. 区切りを短く

- 区切りは「45秒を過ぎた所からの無音（今の SilenceGate・ChunkCutter の見分け方）で区切り、長くても120秒（＋今の maxExtra）」を初めの値にする。
  時計と iPhone の両方。設定に「区切りの長さ」（短め=2分まで／ふつう=5分まで）を足し、初めは短め。
- 区切りが増えても困らないか確かめる: 時計の送る回数と電池・PC の仕事の数・夜の聞き直し・会話のまとまり（ConversationLog の
  区切り方）・クラウドの票や Groq の回数（区切りごとに数えているもの）。区切りごとに使う回数の上限があるものは、
  短くした分だけ増えすぎないようにする。
