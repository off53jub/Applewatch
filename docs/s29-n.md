## 穴（コードを読んで確かめたこと）

1. **答えた組が 0（11/24〜26）**: 家の PC の答えた組（`pc/s24night.answer_pairs` ← `pc/s23voice.answers`）は、
   `inbox/app_feedback.jsonl` の `same_person`（merged/different）と、確かめ待ちの `vp-…`（yes/no）だけを読む。
   アプリでこの 2 つを出す所は、どちらも s24 の 当1（2026-11-24）で既定オフになった「同じ人かも」の問い（`S24AskSettings.samePersonAskKey`）
   の後ろにあり、11/24 から出ていない。ほかの名前付けの答え（名前を付けた・まとめた・移した）はもともと家の PC へ送っていなかった。
   ＝ 日付の合い方から、これが 0 の原因と見ている（**仮説**。実機の `app_feedback.jsonl` で s29_kind の行が増えるのを見て確定する）。
2. **母艦の「この人物N はだれ」の答えが人に届いていない**: `S20Book.answer` は答えを母艦へ送るだけで、端末の人の名前付け・まとめは
   何もしていなかった（確かめた）。`S29NReviewApply`（`S20Book.answer` から 1 行）で、kind `voice`・group `voice_top` の問いの答えを
   端末の人に届ける: 名前のある人と同じ名前ならその人にまとめる（`assign`・戻せる）、自分なら自分に、新しい名前なら名前を付ける、
   「知らない人」なら quiet、「分からない」「あとで」などは何もしない。番号の人が端末に名前の無い人としていなければ何もしない。
   1 行の問い（`speaker_line`）では人全体の名前を変えない。既定オン（本人の答えのときだけ動く）。
   **これより前の答えは端末に答えの中身が残っていないので、さかのぼって届けられない**（母艦が同じ問いを出し直すか、答えを返してもらう必要がある）。

## 送る形（声22。POST /feedback。家の PC → 母艦の inbox/app_feedback.jsonl）

前の形 `{"kind":"same_person","id","value","day"}` のまま、省ける `s29_*` を足す（今の家の PC は前の 4 つだけを残して受ける）。

```json
{"kind":"same_person","id":"g29-1","value":"merged","day":"2026-11-27",
 "s29_kind":"merged",
 "s29_pairs":[{"same":true,"ids":["12","7"],
               "people":[[{"audio":"20261126-090000.m4a","start":1.0,"end":4.0}],
                         [{"audio":"20261125-100000.m4a","start":2.0,"end":5.0}]]}],
 "s29_ids":["12","7"], "s29_group":"g29-1", "s29_at":"2026-11-27T09:00:00+09:00"}
```

- `s29_kind`: `move`（行・ひとこまを別の人へ）・`keep`（このままでよい）・`named`（名前を付けた）・`merged`（まとめた）・
  `unknown`（知らない人）・`split`（まとまりに別の人がいた）。`value` は前の形に合わせ、move・keep・named・merged は `merged`、
  unknown・split は `different`。
- `id`: まとまり全体を同じ人（merged・named）か、同じ人ではない（split）と答えたときは **家の PC の `s29_groups` の id**
  （前の形のままでも、家の PC が `groups_with_samples` に `s29_groups` を入れれば組の答えになる）。ほかは `s29-<種類>-<ミリ秒>-<しるし>`。
  unknown はまとまりの id を使わない（「別の人の組」ではないため）。端末の中のまとまり（`local-…`）の id は送らない。
- `s29_pairs[].people` は家の PC の `answer_pairs` の `people` と同じ形（見本は 3 つまで・0.3〜30 秒・音声の名前に道を含まない）。
  ids の `"line"`・`"clip"` は行・ひとこまだけの見本。片方の見本が無い組は送らない。
- 夜の整理・自動のまとめは送らない（本人の答えだけ）。
- **PC 担当（s29p）に頼むこと**: `appfeeds.parse_feedback` で `s29_*` を落とさずに残す・`answer_pairs` で `s29_pairs` を組にする・
  `groups_with_samples` に `s29_groups` を入れる。

## 読む形（声19）

`GET /same-person` に省ける `s29_groups: [{"id":str,"labels":["人物12",…],"score":float,"seconds":float,"days":int}]`。
labels のうち「人物N」は名前の無い声、それ以外（名前のある人の名前）は「たぶん ◯◯さん」の手がかりにする。欄が無ければ端末の中でまとめる。
`seconds`・`days` は端末の 7 日の数と大きいほうをしぼりに使う。

## 書く形（声23。当てる担当 S29R が読む）

UserDefaults `s29.withNow` に JSON の **文（String）**: `{"end":1764207200,"ids":["7","8"],"start":1764200000}`（epoch 秒の整数）。
やめたときは空の文 `""`。
