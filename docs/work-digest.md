# 仕事のまとめ（2026-11-08）

職場の Claude（Teams のチャットを読める方）に「この日に何があったか」を聞き、その答えをスクリーンショット・写真か、文字のコピーで LifeLog に取り込む。その日の仕事の動きを残し、自分の宿題をタスクに渡す。

## 職場の Claude への頼み方

次の形で答えてもらう（見出しが欠けても、読めたところだけ使う）。

```
【日付】2026-11-08
【出どころ】
・チーム名＞チャネル名「スレッドの題」（いた人：名前、名前）
・チャット「グループの名前」（いた人：名前、名前）
【決まったこと】
・…
【自分の宿題】
・…（誰から／いつまで）
【ほかの人の動き】
・名前: …
【気になる話題】
・…
【あとで確かめること】
・…
【よく出た言葉】
・…
```

【よく出た言葉】（2026-11-10）は、その日のやり取りに何度も出てきた名前・社名・製品名・専門用語・略語を、言葉だけで1行に1つ（説明は書かない）。聞き取りの言葉の登録の候補に使う。出してよい範囲は勤務先の決まりの中で（外に出せない言葉は、職場の Claude に書かせない・取り込む前に消す）。

【出どころ】（2026-11-10。実機では未確認）は、そのまとめが Teams のどこの話か（チーム＞チャネル、またはチャット。スレッドの題）と、そこにいた人を、1行に1つ。まとめを読むときに、どの場の・誰のいる話かが先に分かるようにする。書き方は自由（アプリは行をそのまま残すだけで、中を分けて読まない）。人の名前も職場の情報なので、出してよい範囲は勤務先の決まりの中で。

### そのまま貼れる頼み方

職場の Claude に、下をそのまま貼る（日付は、聞きたい日に直す）。表で答えられると写真の読み取りで崩れ、見出しが無いと分けて読めないので、きまりを先に書いてある。アプリの仕事のまとめの画面の「職場の Claude への頼み方をコピー（今日）」と、取り込む画面の上の「職場の Claude への頼み方をコピー」（2026-11-12。取り込む画面の日付の日の分）でも、日付を入れた同じ文をコピーできる（2026-11-10。中身は `LifeLog/WorkDigestViews.swift` の `WorkDigestPrompt`。直すときは両方）。

2026-11-10 から、【出どころ】の行の頭に［1］［2］の番号を付け、ほかの見出しの項目の終わりにその番号を書いてもらう（項目ごとに、どこの話かが分かるように）。番号の無い答えも、今までどおり読める。

```
2026-11-10 の Teams のやり取りを読んで、下の形だけで答えてください。

きまり
・見出しは下の【 】をそのまま使う。順番も変えない。

・【出どころ】には、読んだ場所（チーム＞チャネル、またはチャット）とスレッドの題を、1行に1つ書く。行の頭に［1］［2］と番号を付ける。そこにいた人も書く（多いときは、発言した人だけでよい）。
・ほかの見出しの項目は、行の終わりに、どの出どころの話かを［1］のように番号で書く。

【日付】2026-11-10
【出どころ】
・［1］チーム名＞チャネル名「スレッドの題」（いた人：名前、名前）
・［2］チャット「グループの名前」（いた人：名前、名前）
【決まったこと】
・…［1］
【自分の宿題】
・…（誰から／いつまで）［1］
【ほかの人の動き】
・名前: …［2］
【気になる話題】
・…［1］
【あとで確かめること】
・…［2］
【よく出た言葉】

```

休み明けなどに何日分かをまとめて聞いたときは、日ごとに【日付】から書いてもらえば、アプリが日ごとに分けて入れる。

## アプリでの使い方

- 下のタブ「タスク」の右上の＋ →「仕事のまとめを取り込む」。または「やる」のいちばん下の「仕事のまとめ」→「取り込む」。
- 「写真・スクショを選ぶ」（何枚でも。選んだ順につなぐ）・「写真を撮る」・「ペースト」で文字を入れる。足すたびに文の後ろに続く。
- 読み取った文字は、その場で直せる。日付は文の【日付】から入る（無ければ今日。直せる）。
- 「入れる」で残す。一覧は日ごと（新しい日から）。押すと読む、左へ払うと消す（たずねてから）。
- **退勤の頃の知らせ**（2026-11-10。実機では未確認）: 一覧のいちばん上の「退勤の頃に知らせる」（はじめはオン・時刻は 17:30。iPhone だけ）。職場の行を書いた日で、その日のまとめがまだ入っていないときだけ、その時刻に1回「今日のまとめを取り込みましたか」と知らせる。知らせに会話の中身は入れない。今日のまとめを入れると出さない。時刻を過ぎてから職場の行がはじめて書かれた日は出さない（翌日に回さない）。
- **出どころ**（2026-11-10。実機では未確認）: 【出どころ】の行は、取り込む画面の「出どころ」と、まとめを開いたときのいちばん上に出る。一覧の小さい字にも数が出る。見せるだけで、人の帳・言葉の登録・タスクには何も足さない。
- **見出しが見つからないとき**（2026-11-10。実機では未確認）: 文字はあるのに決まった形の見出しが1つも読めないときは、取り込む画面の文字の下に、その知らせを出す。そのまま入れることもできる（文のまま残す。宿題はタスクに入らない）。

## 読み方（`LifeLog/WorkDigest.swift` の `WorkDigestParser`）

- 見出し: 空白を除いて、かっこ（【】・[]・［］・「」など、読み違いも）で始まるか閉じる行、または見出しだけの行。「・宿題は…」のような箇条書きの行は見出しにしない。
- 日付: 全角の数字も読む。`2026-11-08`・`2026/11/08`・`2026年11月8日`。【日付】の中なら年の無い `11月8日` も今年として。見出しが読めなくても、年の付いた日付があれば使う。
- 箇条書き: 「・」「･」「•」「·」「-」「.」「1.」など。印の無い行は前の項目の続き（折り返し）。日本語の字のあいだの空白は除く。「なし」「特になし」は項目にしない。
- 出どころ: 見出しは「出どころ」「出所」「抜粋元」（「出典」は見出しにしない。ふつうの文の行と読み違えるので）。行はそのまま残す（印の無い行は前の行の続き。空白の違いだけの同じ行は1つにする。重なったスクショをつなぐと同じ行が2回出るので）。中の名前は読み分けない。
- よく出た言葉: 1行に1つでも、「、」「,」「／」「;」で区切って並べてあっても読む（半角の「/」では分けない。`CI/CD` のような言葉があるので）。「（」「：」「→」「＝」から後ろは説明とみなして落とす。30字を超えるものは言葉ではないとみなして使わない。同じ言葉（大文字小文字・空白の違いだけ）は1つにし、1つのまとめで30個まで。印の無い行も前の行につながず、1つの言葉として読む。
- 自分の宿題: 終わりの（）の中を「／」「、」などで分け、「〜から」を頼んだ人、「〜まで」を期限の言い方にする。「誰」「いつ」のままのものは使わない。`11/10` などの日付が読めれば期限の日も（年をまたぐ分も見る）。
- 前置きの文（2026-11-10）: 見出しのすぐ下、はじめの箇条書きの印より前に書かれた行は、つないで1つにし、文になっている（「。」がある）か「：」で終わるものを前置きとみなす（`isLead`）。まとめには残すが、【自分の宿題】の前置きはタスクにしない（`Parsed.homeworkLead`・`homeworkTasks`。保存はしない）。頼んだ人・期限の付いたもの（「…（Aさんから／11/10まで）」）と、文になっていない行は、今までどおり宿題。箇条書きが1つも無い見出しは、今までどおり1行ずつ読む。
- 出どころの番号（2026-11-10。`WorkDigestParser.sourceTags`・`sourceNumber`・`sourceMap`）: 項目の終わりの、番号だけが入ったかっこ（「［1］」「［1・2］」「[2]」「【1】」。全角の数字も）を、終わりから続くだけ外す（「（11/10まで）」のような番号以外の入ったかっこは外さない）。宿題の頼んだ人・期限は、番号を外してから読む。【出どころ】の行の頭の番号と、「（いた人」より前を短い名前にする。番号は取り込んだ文と `sections` にそのまま残り、読むとき（画面・検索・質問の材料・タスク）に外す。
- 何日分か（2026-11-10。`WorkDigestParser.splitDays`）: 【日付】の行で区切り、日付の違うものが2つ以上あるときだけ分ける（1つ目より前の文は1つ目に入れる）。
- 探す・質問の材料（2026-11-10。`Pipeline.workDigestLines`・`searchWorkDigests`・`workDigestMaterial`）: まとめを見出しつきの行にして使う（決まった形でないまとめは、文を1行ずつ）。同じ日の同じ行（取り込み直したもの）は1つだけ。質問の材料は、探す言葉・人を含む行だけ（「仕事のまとめ」と見出しの言葉も見るので、「仕事」「宿題」と聞けば当たる）。期間を言わなかった質問は前の日のまとめからも探し、期間だけを言った質問はその期間のまとめをまるごと。期間も手がかりも無い質問には入れない。全体の4割まで（会話が1つも無ければ全部）。

## 守ること

- 言語モデル（2026-11-10 に本人の決定で変えた）: 取り込み（文字の読み取り・見出しの分け方・宿題の取り出し）には、言語モデルを使わない（クラウドも端末内も。文字の読み取りは iPhone の中の Vision）。「記録に質問する」の材料には渡す。まとめは職場の中身なので、材料に入るときは職場の会話と同じ扱いにし、設定「職場の会話はクラウドの言語モデルに出さない」のときは外に送らず、端末内の言語モデルで答える（設定そのものは変えていない）。「記録」の検索は言語モデルを使わない。前は「言語モデルには送らない（クラウドも端末内も）」決まりだった。出してよい範囲は、今までどおり勤務先の決まりの中で。
- 【よく出た言葉】は見せるだけで、言葉の登録には自動で足さない（登録した言葉はクラウドの文字起こしにヒントとして渡るので、足すかどうかは本人が1つずつ決める）。保存は `work-digests.json` の `sections.words`（あとから足した項目。前に入れたまとめには無い）。
- 【出どころ】は見せるだけ。中の名前を、人の帳（人・名前・声）や言葉の登録につなげない・足さない。保存は `work-digests.json` の `sections.sources`（あとから足した項目。前に入れたまとめには無い）。1つ1つの項目がどのスレッドの話かは持たない（まとめ1つに、出どころの並びが1つ）。
- 退勤の頃の知らせは、その日に職場の行を書いたかどうかの数（`work.lines`）と、その日のまとめがあるかだけを見る。設定は UserDefaults の `workDigest.reminder`・`workDigest.reminderMinute`。
- 保存は新しいファイル `work-digests.json`（端末ごと・同期しない）。読んでから使い、読めないファイルは上書きせず `work-digests-unreadable.json` に脇に置く（頼まれごと帳と同じ）。毎日の控えにも入れる。
- 宿題はタスクの「やる」（仕事・`work = true`）に入れる。職場の Claude がもう選んだものなので、2026-11-09 から確かめ待ちを通さない（前は「確かめ待ち」に入れ、直接「まだ」には入れなかった）。種類の印は前からある「1日のまとめから」（`summary`）を使い、`tasks.json` の形は変えていない。同じ日の・よく似たものはタスクの帳が足さないので、同じまとめを二度入れても宿題は増えない。
- 写し: iPhone はドライブの「仕事のまとめ」ドキュメント（新しい日から200件まで・まるごと書き直す）と、同期フォルダの「仕事のまとめ.json」（全部。端末の同期では読まない名前）に書く。iPad は写さない（頼まれごと帳と同じ）。
