`pc/s34pswitch.py`（自8・自9）。確かめは `pc/v34checks_s34p.py`（v33 の最後から続けて呼ばれる）。

どれも 0 円・言語モデルなし・ダウンロードなし。声の特徴は `HOME/voices/<日>.npz` の今までのもの（新しく測らない）。
記録の話し手は変えない・人をまとめない・名前を付けない／変えない。動いている LifeLog PC は替えない（次のリリースで入る）。

## 口
| 口 | 中身 |
|---|---|
| `GET /s34`（Bearer） | 母艦の `state/s34_for_app.json` をそのまま返す。大きすぎ（12MB 超）・壊れ・無い・止めてある・母艦なし → `{"available":false,"reason":…}`。features `"s34"`（ファイルがあって止めていないとき）。止める: 母艦の `state/s27_work_config.json` に `"s34p": {"s34": false}` |
| `HOME/s34p_status.json`（K34-2） | `{auto_switch:[…], self_samples:{added, scenes:{home,work,out}}, people_samples:{added, waiting}}` と省ける `tuned`。名前は入れない（数だけ） |
| `GET /voice-samples`（今の口） | 自6 の「自分」（speakerID `me`・見本ごとに `scene`）と、自7 で採用した人を足す（`tier: "tentative"`・`auto: true`・`evidence_kinds: ["scene","voice"]`） |
| `GET /self-voice`（今の口） | 省ける `s34_auto`: `{scenes:{home,work,out}, record_needed}`（3 場面そろえば `record_needed: false`） |
| `POST /work/digest`（今の口・円1） | 形を変えずに通ることを確かめた（下） |

K34-2 の数の意味: `self_samples.added`＝この回に新しく入った自分の見本の数・`scenes`＝今ある場面ごとの数（1 場面 5 個まで）。
`people_samples.added`＝採用した人の数（今まで）・`waiting`＝2 回目の日を待っている人の数。

## 自6 自分の声の見本が自動で集まる条件
- **家でひとり**: 会話の場所が家（会話の place に「自宅」・母艦の滞在が自宅・区切りの scene が home のどれか）で、その会話の話し手の印が自分だけ（ほかの声・テレビなどの声なし）・自分の行が 2 行以上（仮）。
- **PLAUD でいちばん近くて多い声**: 母艦 `digests/canonical/<日>.json` の録音ごとに、いちばん多い PLAUD の話し手（45% 以上・10 行以上・仮）の行と結べたアプリの行（時刻 3 秒・話し手の番号）。アプリが人物N にしていても拾う（職場の「自分を拾えた割合 0%」の分）。
  - 「近い」: s22 の levels があれば、行の大きさ ≥ 区切りの声の真ん中 − 3 dB（仮）。
  - 家でひとりの声の真ん中があれば、それと 0.5 以上（仮）。
  - どちらの確かめもできない行は使わない。
- 行は 2〜10 秒・騒がしい印・周りの音・テレビの声なし・音声が PC にあるもの。場面は 家の手がかり → `work: true` → 外 の順。
- 本人が 3 通り録る操作（声14）は、3 場面に見本がそろえば要らない（`/self-voice` の `record_needed`）。
- 置き場: `HOME/s34p/self-samples.json`。止める: config.json の `"s34p_self_samples": false`。

## 自7 よく会う人の見本
- 確かな場面: 予定の相手が 1 人（`archive/calendar`）・LINE で直前に約束（`state/talk_guess_for_pc.json` の理由に LINE）・出席者の分かる会議（`state/s32_meeting_people_for_pc.json`）。
- 1 人の場面ではいちばん長い名前の無い声、会議で 2 人以上なら出席者の声の真ん中といちばん近い（0.45 以上・2 番目と 0.05 差・仮）声だけ。自分の声の真ん中に 0.6 以上近い声は除く。
- 別の日の 2 回の声の真ん中が 0.6 以上（仮）でそろったら採用。採用は残る（`HOME/s34p/people-samples.json`）。
- 名前が記録にもう出てくる人（speakerID のある名前）だけ。人は作らない・まとめない・名前は変えない。止める: `"s34p_people_samples": false`。

## 自8 物差しの対象にした影
物差しは 2 つ（本人の答えは待たない）:
- **時計と iPhone の 2 本**が同じ発話を同じ印で書いた所 → 同じ人・違う人の組。
- **PLAUD と合った所** → 同じ録音で PLAUD の話し手が同じか。PLAUD の分けも正解ではないので「合う割合が上がったか」を見るだけ（仮）。

| 名前 | 今の切り替え | 物差し | 本番の中身 |
|---|---|---|---|
| snorm（声9） | `s29p_snorm_score` | 機械の組の AUC（s-norm 対 今の点） | `GET /same-person` を s-norm の順に |
| canonical（声5） | `s29p_canonical` | PLAUD と合った所の当たり（分け直し 対 iPhone） | `GET /s29/canonical` に付け直し案 |
| day_diar（聞4） | `s26p_day_diar` | 同（1 日まるごとのかたまり 対 iPhone） | 夜に 1 日まるごとの分けを毎晩作る |
| boost（聞15） | `s26p_boost` | 持ち上げた行の PLAUD と合った字 | **本番の口がまだ無い**（測るだけ） |
| separate（聞6） | `s26p_separate` | — | **判断が要る**（speechbrain を入れるか。入れない） |
| denoise_embed（声3）・two_mic（声2） | 各々 | — | 本番の口がまだ無い（測るだけ） |

- 毎晩、昨日の数を `HOME/s34p/measures.jsonl` に。7 日ごとに 7 日ぶんを合わせて決める（`HOME/s34p/switch.json`）。
- 影 → 本番: 数が need 以上・測れた日 3 日以上・新しいやり方 ≥ 今 + margin（どれも仮）。
- 本番 → 戻す: 次の週に 新しいやり方 < 今、か 前の週 − 0.03 より下。戻したら 14 日は本番にしない（仮）。
- 切り替えは `HOME/s34p/switch-log.jsonl` に 1 行。本人が config.json にその名前を書いていれば本人の値が上（自動では動かさない）。
- 当て方: `s26pc.on`・`s29pc.on`・`s29pgate.snorm_mode`・`s29pgate.apply_snorm` を包む（config.json は書き換えない）。止める: `"s34p_auto_switch": false`（数えるだけ）。
- s29 の summary の「自動では切り替えない」の文は、s34 の分を数えていない（直していない）。

## 作れなかった物

- 「2 日・3 分」は母艦側の数（家の PC には無い）。
