## 規則（report が無いとき。どれも仮）

- 柱（6 つ・画面の順）: テストの進み（打鍵）・不具合とチケット・テスト用のカード・日程と節目・仕様と画面の決めごと・報告・会議。言葉は `S30WRules.pillars`、当てる順は 日程 → カード → 不具合 → テスト → 仕様 → 報告（ひな形と同じ）。トピックの名前が当たればそのトピックの項目は全部その柱、当たらなければ項目の文で。案件全体の話（親そのもの）と「まだ案件に分けていないもの」は名前では当てない。ほかの部署の話は外の箱、どれにも当たらないものは「まだどの柱にも入らないもの」。中身の無い柱は出さない
- 今日の一手: 自分の案件（とまだ分けていないもの）の開いている件のうち、急ぎ・自分の番を 急ぎ → 期限の近い順 → 古い順で 3 つ。相手待ちは 期限の近い順 → 長く待っている順
- 状況の 1 枚: 親でまとめた自分の案件ごとに 3 つまで。5 日動いていなければ「止まっている」、急ぎがあるか 6 日以上そのままが 3 つ以上なら「注意」、ほかは「順調」。動いたは 3 日以内に決まったこと
- 道のり: 自分の案件のトピックの節目
- 柱の 1 行: 開いている数（急ぎ・自分の番・相手待ち）・6 日以上の数・3 日以内に決まったことがあるか

## 送り方（K30-2）

1. 取り込む画面で「入れる」→ 今までどおり端末に保存（ドライブの写しも今までどおり）。
2. 保存のあと、保存したばかり（2 分以内・仮）でまだ送っていないまとめ（20 件まで）を、`POST /work/digest` に `{"entries":[…]}` で送る。1 件は端末の `work-digests.json` と同じ `JSONEncoder`（キーの順をそろえる・日付は既定の書き方）で書く。鍵は S27WBook と同じ HomePC のオーナーの Bearer。
3. 送るのは features に `workpush` があるときだけ（hello のあとに覚える）。無い・家の PC の設定が無い・送れない・返事の `available:false`・`run:"off"` のときは、帯に「今までどおりドライブの写しから 15 分ごとに作り直します」と小さく書くだけ。
4. 送れたら「作り直しています」の帯。`GET /work/run` を 5 秒ごと・3 分まで（仮）見て、`idle` になり、送ったあとに `running` を見たか、`finished_at` が送ったころ（時計のずれ 60 秒まで・仮）より後なら終わり。送ったときにもう走っていた（`run:"already"`）なら、送ったあとに始まった回が終わるまで待つ。終わったら `GET /work` を取り直して「作り直しました」。3 分で終わらなければ取り直して「次の回か、引っぱって取り直すと入ります」。
5. 帯は終わってから 10 分（仮）で消える（×で閉じられる）。知らせ（通知）は足していない。

## 既定

- 新しい問い・知らせは増やしていない。言語モデルの呼び出しも無い。中身の文は Tally に書かない（数と種類の名前だけ: `s30w.open`・`s30w.push`・`s30w.push.fail`・`s30w.push.none`・`s30w.push.off`・`s30w.run.done`・`s30w.run.ng`・`s30w.run.late`・`s30w.restore` など）。
- 端末に覚えるもの（UserDefaults）: `s30w.pushOffered`・`s30w.restored`（id → 日）・`s30w.sent`（送った id・200 件まで）。

## ほかの担当との約束

- タブ担当（S30T）: ContentView は `S30WTab()` を呼ぶだけ。ContentView・TaskBook のタブの中身は変えていない（TaskBook の部品 `TaskRow`・`TaskEditView`・`TaskReply` と帳の関数をそのまま使った。private を外したものは無い）。S30T の枝の `TaskBookView(scope: .work)` はこの枝に無いので、同じことを部品で組んだ（まとめのときにどちらかに寄せてよい）。
- S30T の「直す」の「タスクの候補は『タスク』で」の穴: 仕事タブの「自分のタスク（仕事）」のいちばん上に、今日の候補の仕事の分（同じ 1 日 3 件の枠）を「入れる／違う」つきで出しているので、仕事だけの日はここで片づけられる（行き先の文字を変えるなら S30T の `S30TTabs.tab(forTasks:)`）。
- 仕事タブにいるときの `.work(.home)` は S30T が前の一覧をシートで開く。仕事タブの中の「前の一覧」は NavigationLink で `S27WHomeView`（Face ID の鍵を二重にしないため `S27WRootView` ではなく中身だけ）。
- 母艦（s30m）: report の project の id は、トピックの `parent` と同じ id（顧客の名前はそのまとまりから取る）。`numbers` は空のことがある（そのときは progress か開いている数）。`unit` の null はそのまま読む。
- 家の PC（s30p）: `POST /work/digest`・`GET /work/run`・features の `workpush` の形は K30-2 のまま。
