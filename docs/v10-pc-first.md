# PC から先に記録に入れる（2026-11-07）— 時計の区切りの音声を待たない（版 10）

時計から iPhone への受け渡し（WatchConnectivity）は Apple に絞られて、何時間も遅れることがある（この日は最大6時間）。
いっぽう時計は家の PC にも直接送るので、PC は iPhone に音声が届くよりずっと前に文字にし終えている。
そこで iPhone は、**PC の答えで先に記録に入れ、音声はあとから付ける**。

どれも実機ではまだ確かめていない。PC の `/hello` の features に `watchroute` があるときだけ動く（無ければ今までどおり）。

## 流れ

1. 取り込みのたび（アプリを開いたとき・見えない通知・裏の処理・時計の合図）に、1分に1回まで
   `GET /jobs?origin=watch` で、時計から直接届いた仕事の一覧を見る。
   見えない通知（kind `job`）が届いたときは、1分を待たずに見る。
2. 選ぶのは: でき上がっている（`done`）・時計の区切りの名前（`…-w.m4a`）・2日より新しい・
   まだ文字にしていない（録音の帳簿 `recordings.json` に無い）・音声がまだ iPhone に無い、もの。古い順に1回24個まで。
3. `GET /jobs/<名前>` で答えを受け取り、ふつうの PC の答えと同じ読み方（`HomePC.jobState`）で行にする。
4. 音声の要らない手順は、音声から文字にするときと同じにする:
   話題・予定・連絡先の言葉、登録した書き方、言語モデルの直し（2つ目のモデルとの見比べも）、数字そろえ、
   多数決の確からしさと票、行の終わり。iPhone と時計の両方で録っていた時間は、今までどおり良いほうを選ぶ（Merger）。
5. 録音の帳簿に「文字にした」として残す（始まりは名前の時刻、終わりは PC の答えの `chunk_end`、無ければ5分後。
   `source` は `watch`、新しい項目 `pcFirst: true`）。抜けの地図では録れていた時間になる。
6. 使い終わった答えは、今までどおり PC から消す（`DELETE /jobs/<名前>`。PC は音声を記録の置き場に移して残す）。

## 音声を待つとき（PC から先に入れない）

音声が無いとできない手順がある時間は、今までどおり音声が届いてから文字にする:

- 寝ている時間（端末内の聞き取りだけにして、小さな声を外すため）
- 周りの人の声を外す時間（「周りの声を外す」が「職場にいるときだけ」で職場にいる・仕事の予定の最中、または「いつも」のとき。
  声の大きさを見るため）

## 音声があとから届いたとき

- 帳簿に `pcFirst` がある区切りは、文字にし直さない（行を二重にしない）。音声は、文字にし終えた音声と同じ置き場所
  （`Documents/audio`）に移すので、聞き直し・「聞いて直す」・ドライブへの保存・夜の聞き直しは今までどおり使える。
- 届くまでの遅れ（時計→iPhone）は、今までどおり数える。
- 話者の聞き分けがオンなら、行を書き出したあとで、話者の無い行に話者を付ける（1回に6区切りまで）。
  付け方は「話者を直す」と同じ（記録とドキュメントの行をその場で直す）。名前のある人を合わせたり名前を変えたりはしない。
  手で直した行・話者のある行・放送の行には触らない。「記録に出さない」にした人の声だった行は、話者なしのまま残す。

## しないこと（音声が無いので）

端末内の聞き取りとの見比べ、声の区間、騒がしさ・こすれ・背景の音、クラウドの票・有料の票、話者で行を分けること。
会話の見出しとまとめは、話者を付ける前の行で作ることがある（あとから話者を付けても、見出しは作り直さない）。

## 数える

- 自己点検「文字になるまで」: 「PC から先に記録に入れた（今日）」の数。
  「PC から先に入れた（直近24時間）」の数と、録音の終わり→記録に入るまでのふつうの時間。
  ふつうの中央値（時計→iPhone などの区間）には混ぜない。`/diag` の `state.latency` には `pcFirstCount`・`pcFirstTotal` を足す。
- 効き目の帳（Tally）: `pcFirst.applied`（入れた区切り）・`pcFirst.audioLater`（あとから届いた音声）・
  `pcFirst.speakers`（あとから話者を付けた行）・`pcFirst.speakersSkipped`（付けられなかった区切り）・
  `pcFirst.waitAudio`（音声を待った区切り）・`pcFirst.push`（文字起こしができた知らせ）。

## 保存するもの

- `recordings.json` の区切りに `pcFirst`（無ければ nil。前の形のファイルもそのまま読める）。
- `latency.json` の時刻と測った値に `pcFirst`（同じ）。
- UserDefaults: `homePCWatchRoute`（PC が対応しているか）・`pcFirstWaitAudio`（音声を待つと決めた区切りの名前。2日で忘れる）・
  `pcFirstSpeakers`（話者を付ける区切りの名前）。どれも名前だけで、会話の中身は入れない。
