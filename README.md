# LifeLog

iPhone で会話を録音し、日本語に文字起こしして、Google ドライブの「LifeLog」フォルダにある日付ごとの Google ドキュメントへ自動で追記するアプリ。ChatGPT や Claude の Google ドライブ連携から検索して使う。

- 録音: 5分ごとに区切る（AAC 16kHz モノラル）。ほぼ無音の区切りは捨てる。
- 文字起こし: ふだんは iOS 26 の SpeechAnalyzer（端末内、無料）。API キーを入れると Groq の Whisper large-v3（無料枠あり）か OpenAI の gpt-transcribe（有料）に切り替えられる。
- 保存: Google Docs API で `HH:mm:ss  発言` の形で追記。追記に成功したら音声を消す。
- Mac なしで開発する: GitHub Actions の macOS でビルドし、TestFlight に配る。

## 無料で入れる（Apple Developer Program なし）

Windows の [Sideloadly](https://sideloadly.io/) を使い、無料の Apple ID で署名して iPhone に入れる。

1. GitHub の Actions →「TestFlight」の最新の実行 → Artifacts から `LifeLog-unsigned-ipa` をダウンロードして展開する。
2. Windows に Sideloadly と iTunes（Apple 公式サイト版）を入れ、iPhone を USB でつなぐ。
3. Sideloadly に IPA をドラッグし、Apple ID を入力して Start を押す（捨てアカウントの Apple ID がおすすめ）。
4. iPhone の「設定」→「プライバシーとセキュリティ」→「デベロッパモード」をオンにし、「一般」→「VPN とデバイス管理」で自分の Apple ID を信頼する。

Actions のビルドに「Google の ID が未設定」という警告が出ていたら、Secrets がまだ読めていない。Secrets は入れる前に始まったビルドには反映されないので、入れたあとのビルドで確かめる。

制限:
- **7日で起動しなくなる。** 週1回、同じ手順で入れ直す（データは残る）。Sideloadly の自動更新を使うと、PC と iPhone が同じ Wi-Fi にあれば自動で入れ直せる。
  - 期限はアプリが自分の署名（`embedded.mobileprovision` の ExpirationDate、`Provisioning.swift`）から読み、**1日前と3時間前に通知**する。36時間を切ると「今日」の「いまの様子」にも出る。自己点検の「署名の期限」にも出る（TestFlight で入れたときは期限が分からないので出さない）。
  - 同じ期限を、同期フォルダの「アプリの状態（端末）.json」（1時間に1回ほど。会話の中身・名前は入れない）で家の PC に伝え、PC の `Watch-Freshness.ps1` が LINE でも知らせる。
- 無料の Apple ID で入れられるアプリは同時に3つまで。
- Apple Watch アプリは、無料の署名でうまく入らないことがある（未確認）。
- バンドル ID が `com.off53jub.lifelog` から変わった場合は、Google の OAuth クライアントもその ID で作り直す。

この方法では、Google の準備（下の2）と、GitHub の Secrets の `GOOGLE_CLIENT_ID` と `GOOGLE_REVERSED_CLIENT_ID` だけが必要。

## 最初の準備（一度だけ）

### 1. Apple
1. [Apple Developer Program](https://developer.apple.com/programs/) に登録する。
2. [App Store Connect](https://appstoreconnect.apple.com/) で「マイ App」→「＋」→「新規 App」。バンドル ID は `com.off53jub.lifelog`（一覧に無ければ、[Identifiers](https://developer.apple.com/account/resources/identifiers/list) で先に登録する）。
3. 「ユーザとアクセス」→「統合」→「App Store Connect API」で、**Admin** 権限のキーを作る。`.p8` ファイル、キー ID、Issuer ID を控える。
4. チーム ID を [Membership](https://developer.apple.com/account#MembershipDetailsCard) で確認する。

### 2. Google
1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作り、**Google Drive API** と **Google Docs API** を有効にする。
2. 「OAuth 同意画面」を「外部」で作り、テストユーザーに自分のアカウントを追加する。
3. 「認証情報」→「OAuth クライアント ID」→ 種類「iOS」、バンドル ID `com.off53jub.lifelog`。クライアント ID（`xxxx.apps.googleusercontent.com`）を控える。

### 3. GitHub の Secrets
リポジトリの Settings → Secrets and variables → Actions に追加する。

| 名前 | 中身 |
|---|---|
| `APPLE_TEAM_ID` | チーム ID |
| `ASC_KEY_ID` | API キー ID |
| `ASC_ISSUER_ID` | Issuer ID |
| `ASC_KEY_P8` | `.p8` ファイルの中身をそのまま |
| `GOOGLE_CLIENT_ID` | `xxxx.apps.googleusercontent.com` |
| `GOOGLE_REVERSED_CLIENT_ID` | `com.googleusercontent.apps.xxxx`（上を逆にしたもの） |

## ビルドと配信
`main` に push するか、Actions の「TestFlight」を手動で実行する。10〜20分ほどで App Store Connect に届き、TestFlight アプリから iPhone に入れられる（内部テスターに自分を追加しておく）。

## 使い方
1. 「Google でログイン」。
2. 「録音を始める」。画面を消しても録音は続く。電話などで止まったら、アプリを開いて再開する。
3. ドライブの `LifeLog/2026-10-16` などのドキュメントに、時刻つきで追記されていく。

### 文字起こしされるタイミング
- 時計の録音は5分ごとに区切って iPhone に送る（送る時刻は watchOS が決める。iPhone が近くにあれば、ふつうは数分以内）。
- 届くとアプリが裏で起こされて処理する。iOS が裏で動ける時間を短く区切るので、終わらなかった分は次の機会に回る。
- 次の機会は、アプリを開いたとき、iOS がときどき起こしたとき（15分以上の間隔で、使い方に応じて iOS が決める）、充電中で通信できるとき（まとめて処理）。
- 「文字起こし待ち」の件数が、届いたのにまだ処理していない数。
- 「今日」タブの「時計の遅れ」で、区切りを録り終わってから届くまでと、届いてから文字になるまでの時間を見られる（直近24時間のふつうの長さといちばん遅い長さ、12分以上遅れて使えなかった時間、待機モードと時計の低電力モードの状態）。測るだけで、記録には影響しない。`watch-delays.json` に直近600個を残す。
- 「待機モード」（初めはオン）にすると、無音を流してアプリを裏で起こしておくので、届いた区切りをすぐ処理する（区切り5分＋送る時間の遅れ）。電池を少し多く使う。アプリを上にスワイプして終わらせたり再起動したりすると止まるので、一度開く。

### iPhone と時計の両方で録っているとき
- 同じ時間帯を両方で録っていたら、30秒ごとに聞き取りの確からしさ（聞き取れた文字数 × Whisper の確からしさ）を比べ、良いほうの文だけをドキュメントに書く。同じ話が二重に書かれることはない。乗り換えは相手がはっきり良いとき（1.2倍）だけ。
- 時計が録音中は、時計の区切りが届くのを待ってから書く（最長12分。それより遅れたら iPhone の分だけで書き、あとから届いた時計の同じ時間帯は捨てる）。
- 片方しか録っていない時間帯は、そのまま書く。
- アプリの「これまでの記録」では、時計の音から書いた行に時計の印が付く。
- 両方で録るとクラウドの文字起こしと補正の無料枠を2倍の速さで使う。使い切った分は端末内の文字起こしで済ませる。

## 高精度の文字起こし（クラウド）
アプリの「サービスと API キーの設定」で、使うサービスを選んでキーを貼り、「高精度で文字起こし」をオンにする。

- **Groq（無料）**: Whisper large-v3。[console.groq.com](https://console.groq.com/keys) でアカウントを作り、API キー（`gsk_` で始まる）を作る。カード登録は要らない。無料枠は1日 28,800 秒（8時間）分まで。使い切ったら、枠が別にある次点の whisper-large-v3-turbo（こちらも8時間）に切り替え、それも使い切ったら端末内の文字起こしで済ませる。画面の「直近の文字起こし」に、どれを使ったかが出る。区間ごとの時刻も付く。
- **OpenAI（有料）**: gpt-transcribe（1分 $0.0045）。[platform.openai.com](https://platform.openai.com/) の Billing でクレジットを入れてからキーを作る（ChatGPT の有料プランとは別会計）。文ごとの時刻は返らないので、区切りの長さを文字数で割り振って時刻を付ける。アプリの「月の上限」を超えたら、月が変わるまで端末内に戻る。

共通:
- 先に端末内で文字起こしし、何も聞き取れなかった区切りはクラウドに送らない。
- 「聞き取ってほしい言葉」に人名や社名を1行ずつ書くと、その表記で書き起こされやすくなる。
- キーが無効・残高切れのときは高精度を自動でオフにし、端末内の結果で続ける。通信できないときは音声を残してあとでやり直す。

### 精度を上げるしくみ
- 直前の区切りから続いているときは、その終わりの文を Whisper のプロンプトに入れ、区切りの頭が話の途中でもつながるようにする。キーワードもプロンプトに入れる。
- 「誤変換を言語モデルで直す」（Groq の `openai/gpt-oss-20b`、無料枠）をオンにすると、同音の誤変換や固有名詞の書き間違いだけを前後の文脈から直す。直す前の文は「これまでの記録」に小さく残る。混んでいるときや無料枠を超えたときは、直さずにそのまま使う。
- 有料に切り替えた場合の目安は、1日5時間話して月 $1〜2 ほど（入力 $0.075・出力 $0.30 / 100万トークン、2026-10 時点）。

## 話者の聞き分け（端末内・無料）
「話している人を聞き分ける」をオンにすると、[FluidAudio](https://github.com/FluidInference/FluidAudio) の話者分離モデル（初回に数十 MB をダウンロード）で、区切りごとに「いつ誰が話したか」を調べ、文字起こしの行に `[自分]` `[人物1]` などを付ける。

### 聞き分けのしくみ
1. 区切り（5分）の中で、FluidAudio のオフライン方式（pyannote community-1 の分け方と VBx のまとめ方。録り終わった音をまとめて処理する方式で、FluidAudio の中でいちばん正確）に「同じ声のまとまり」に分けてもらう。
2. まとまりごとに声の特徴を平均し、覚えている人と照らし合わせる。人ごとに声をいくつも覚えておき（iPhone と時計、静かな所と騒がしい所で聞こえ方が違うため）、近いもの上位3つの平均で比べる。1つの区切りで2つのまとまりを同じ人に当てるのは、どちらもはっきり近いときだけ。
3. 職場にいるときは職場の人と「どちらでも」の人を、それ以外では職場以外の人を先に比べる。別の場の人は、よほど近いときだけ選ぶ（職場は「場所」の一覧でスイッチをオンにした場所。場所の記録がオフなら分けない）。
4. どの人にも近くなければ、新しい「人物N」として覚える。3秒より短くて分からない声には名前を付けない。
5. はっきり一致して3秒以上話していたときだけ、その声を覚え足す（自動で覚えるのは新しい20個まで）。
6. 「聞き分けの厳しさ」で、同じ人とみなす近さを変えられる（別の人が同じ名前になるなら厳しめ、同じ人が何人にも分かれるならゆるめ）。

オフライン方式に替えたとき、声の特徴の取り方が変わったので、以前覚えた声は使えなくなった。名前のある人は、覚えている声のひとこま（最大3つ）から自動で取り直す。自分の声は録り直す。

### 登録と手直し
- **自分の声**: 20秒読み上げて登録。何度か録ると（小声・会議の声など）足していく。
- **相手の声**: 「話した相手」の＋から、名前と場（職場・職場以外・どちらでも）を決めて20秒録る。
- **記録から直す**: 「これまでの記録」で行を長押し（または右にスワイプ）→「話者を直す」。直す範囲は「この行だけ」「同じ5分の同じ声」「この声すべて（2人を1人にまとめる）」。直した行の声はその人の声として必ず覚え、消さない。ドキュメントの同じ行も直る。
- **名前を付けてほしい声**: よく話したのに名前の無い声が、話した量の多い順に「話した相手」の上に出る（はじめは10人）。一覧には、その声が話した長い1行と、「もしかして: 〇〇」（呼ばれた名前）も出る。▶︎で声を聞いて名前を付けると、これまでの記録とドキュメントの「人物N」もその名前に変わる。
- **声だけで誰か分からないとき**: 名前の無い声の画面に、手がかりを出す。
  - 「この声が話したこと」: その声が出てきた会話（新しい順に5つ。時刻・場所・予定・見出し・一緒にいた名前のある人）と、そこで話した長い行を3つずつ。行を押すと、その行の声だけが鳴る（同じ音声の次の行まで、最長15秒）。
  - 「名前の候補」（最大4つ）: その声が自分で名乗った名前（「田中と申します」「田中といいます」「〇〇社の田中です、よろしく…」。「〇〇です」だけでは「大丈夫です」なども拾うので、すぐあとに「よろしく」が続くときだけ）、「〇〇さん」と呼ばれたすぐあと（20秒以内）に話していた名前（全期間）、その声が出てきた会話の時間のカレンダーの予定の参加者（新しい会話20個まで。一緒にいたと分かっている人は除く。参加者が4人以上の予定は弱めに数える）、声の近い名前のある人。理由を添えて、当てはまるものが多い順に出す。押すと、名前を付けた人に同じ名前の人（空白・「さん」などを除いて同じ、または「田中」と「田中太郎」のように片方が頭）がいればその人にまとめ、いなければその名前を付ける。押すまでは何も変えない。
  - 名前を付けた人の画面にも「この声が話したこと」が出る（声の見分け違いに気づくため）。
- **1人ずつの画面**: 名前・会う場の変更、覚えている声のひとこまの再生、その場で声を足す、ほかの人とまとめる、忘れる。
- **声のひとこまが何の声か**: ひとこまごとに、同じ音声でその時間に重なる記録の行を探し、その時に話していた文（80文字まで）・日時・場所を出す。その行が記録で別の名前なら「記録では「〇〇」の行」と出す（ほかの人の声を拾っているかもしれない印）。「話した相手」の一覧と「自分をまとめる」の▶︎にも、鳴る声の文を添える。登録で録った声など、記録の行が無いひとこまは今までどおり「声のひとこま N」。
- 名前を付けていない声は、2週間聞かなければ忘れる。
- 保存するのは声の特徴（数値）だけ。外に出るのは持ち主のドライブだけ（同期の「同期」フォルダに登録・手直しの声、毎日の控えの「控え」フォルダにすべての声）。他の人の声を登録したり名前を付けたりするときは、その人の了解を取っておく。
- **テレビ・動画らしい声**: 名前の無い声のうち、直近14日の行（5行以上）の7割以上が、テレビ・動画の会話や行・背景の音がテレビや音楽・前後3分に自分が話していない、のどれかの声（行の半分以上が家＝場所の名前に「自宅」「家」「実家」を含む会話の声は、3行以上・半分以上で）は「名前を付けてほしい声」「人物Nを整理」（と「今日」の人数）に出さず、「話した相手」の「テレビ・動画らしい声」に畳んで出す。「まとめて忘れる」で名前の無い声だけを忘れる（記録の行はそのまま）。
- **テレビ・動画の声だった**: 名前の無い声の人の画面（と声の見直しの「その他…」）の「テレビ・動画・ラジオの声だった」で、その声とされた行をすべて放送の行（「テレビ」「動画」「ラジオ・音楽」。夜の見分けと同じく元の名前と番号は `heardSpeaker` / `heardSpeakerID` に残す）に書き換え、ドキュメントの同じ行も直して、声を忘れる。名前のある人には出さない（混ざっているだけなら「分ける」でその組だけ）。行そのものを書かないなら、「周りの声と雑音」の「自分とやりとりの無い声を外す」を「いつも」にする。
- **混ざった声を分ける**（2026-11-04 に「2人を分ける」から作り替え）: 人の画面の「声」の「ほかの人の声が混ざっている（分ける）」。その人とされた行（新しい60行か150行。2秒以上）の声を取り、平均の近さでつなぐ方法で、組どうしの近さが0.40より近い間だけまとめて、何組にでも分ける（1行だけの組は「ばらばらの声」にまとめる）。組ごとに「この人の声」（いちばん大きい組ははじめから）・「別の人に移す」（名前のある人・自分・新しい人）・「テレビなどの声」（テレビ・動画・ラジオ・音楽）・「放っておく」を選び、「分ける」でまとめて直す（テレビなどの組は、行を放送の行に書き換え、元の人の覚えている声からその組に近いものを外すだけ。移す組の行の名前を変え、元の人の覚えている声のうち移す組の声のほうが近いものを外して、移す先の声として覚える）。続けて「残りの古い行も、声で振り分ける（300行まで）」で、調べなかった前の行を、いちばん近い組が移した組で、この人の声より0.05以上近いものだけ直す。まだ混ざっていれば、もう一度分ける（直した行は外れている）。
- **（以前の）2人を分ける**: 聞き分けを厳しくしても2人が1人として扱われるとき、人の画面の「声」の「2人の声が混ざっている（分ける）」。その人とされた行（新しい60行か150行。2秒以上話したもの）の声を取り、近さで2つ（声A・声B）に分けて見せる。行を押して聞き、ほかの人のほうを「この声は別の人（分ける）」→ 名前のある人・自分・新しい人を選ぶと、その組の行の名前が変わり（ドキュメントも）、元の人の覚えている声のうち、その組の声のほうが近いもの（近さ0.3未満）を外して、選んだ人の声として覚える（手直しと同じく自動では消さない声、10個まで）。続けて「残りの古い行も、声で振り分ける（300行まで）」で、調べなかった前の行も、分けた声のほうがはっきり近いもの（0.05以上）を直せる。2つの声の中心が近い（0.25未満）ときは「同じ人かもしれません」と出す。
- **声の見直し**: 「話した相手」の上の「声の見直し」に、覚えている声のひとこまのうち、記録ではほかの人の行やテレビ・放送の行と重なっているものが出る（人の画面のひとこまの「見直す」からも）。▶︎で聞いて、「〇〇の声だった（移す）」「合っている」か、「その他…」（ほかの人の声だった＝人を選ぶ・新しい人／自分の声だった／テレビ・動画・音楽の声だった／何人かの声が重なっている／名前の無い声なら「まるごとテレビ・動画の声だった」／分からない＝今は飛ばす）から選ぶ。移す・忘れるは、そのひとこまの音から声の特徴を取り直し、その人の覚えている声のうち同じ声（近さ0.15未満。登録・手直しの声も）を忘れる。移すときは、移す先の人の声として覚える（手直しと同じく自動では消さない声）。「合っている」にしたものはもう出さない（`voiceReviewKept`）。
- **食い違った声を自動で外す**（2026-11-05・既定オン。設定の「話者」で止められる）: 声の見直しに出るひとこま（記録ではほかの人やテレビの行と重なっている）は、見直しを待たずに、処理のたびに6つまで聞き分けから外す（`Pipeline.setAsideMismatched`）。外すのはその音と同じ**自動で覚えた声**だけで、消さずに `voices-set-aside.json`（控えにも入る）に取っておく。登録・手直しの声と同じひとこまは本人が決めた声なので触らず、見直しに残す（もう試さない印 `voiceAsideTried`）。人の画面の「聞き分けから外した声」で聞けて、「この人の声だった（戻す）」で声もひとこまも戻り、「合っている」扱いになって二度と外さない。外したひとこまは、ほかの端末の同期で戻ってこない。
- **自分の声がほかの人の声として覚えられないように**（2026-11-05）: 控えを調べると、井上さんの自動で覚えた声21個のうち20個、ういの6個が、本人の登録の声より自分の登録の声にずっと近く（自分まで0.24〜0.39・本人まで0.7〜0.9）、11/3 以降は「自分」の行が1〜5%しかなかった（11/1 は27%）。迷った声を覚え足すうちに、自分の声がほかの人の声として増えていたため。次の3つで直した。
  1. **外す**（`Pipeline.setAsideOthersVoices`、処理のたび）: 登録・手直しの声がある人の、自動で覚えた声のうち、ほかの人の登録・手直しの声まで0.40以下で、その人の登録・手直しの声より0.20以上近いものを、聞き分けから外して `voices-set-aside.json` に取っておく（音のひとこまが無いので、人の画面の「聞き分けから外した声」に「〇〇の決めた声に近かった、自動で覚えた声 N 個」とまとめて出し、「この人の声だった（N 個を戻す）」で戻せる。戻した声は二度と外さない＝`voiceKeptElsewhere`）。登録・手直しの声が無い人は比べる手がかりが無いので触らない。設定の「食い違った声を自動で外す」で止まる。
  2. **覚え足さない**: 自動で声を覚え足すのは、2番目に近い人より0.10以上近いときだけ。ほかの人の声なのに、身につけたマイクに自分の声くらい大きく（覚えた自分の声の大きさ−3dB以上）入った声は覚えない。
  3. **自分を先に選ぶ**: 自分の声くらい大きい声は、自分とほかの人で迷うとき（差が0.06以内）に自分を選ぶ。1つの区切りで2つのまとまりが同じ人になり、片方が自分の声くらい大きく、もう片方より12dB以上大きいときは、大きいほうを自分にする（自分の声まで0.48以内のとき。こうして決めた声は覚え足さない）。
  すでに書いた行の名前は変えない。直すときは、その人の画面の「ほかの人の声が混ざっている（分ける）」。

## 会話の見出しと1日のまとめ
話が3分途切れるごとに1つの「会話」とみなし、ドキュメントの会話の頭に見出しを差し込む。

```
14:05〜14:40　会社　田中さんと　来週の提案資料の打ち合わせ   ← 見出し2
・提案は A 案で進める
・資料は木曜までに自分が作る
14:05:12  [田中さん] じゃあ来週の…
```

- 内容の見出しと要点（最大3つ）は、Groq の無料枠の言語モデル（`openai/gpt-oss-120b`、長い会話は `openai/gpt-oss-20b` で区切ってから）で作る。Groq の API キーが無いときは、時刻・場所・相手だけの見出しになる。
- 日が変わると、前の日のドキュメントの先頭に「1日のまとめ」（1日の流れ・会った人・決まったこと・やること・話題）を差し込む。1日の流れは「9:00〜11:30　会社　企画会議（田中さん）」のように、近い時間・同じ場所の会話をひとまとめにしたもの。
- 80文字に満たない短い会話（テレビの音や独り言など）には見出しを付けない。
- 見出しは、次の区切りが届いたときかアプリを開いたときに付く。録音が止まっていると、最後の会話の見出しは次に開くまで付かない。
- Groq の無料枠が足りずに見出しを作れなかった会話は、あとから少しずつ埋める（1回に1万2千文字まで。新しい日から。作れなければ次の機会にやり直す）。ドキュメントの見出しも置き換えて、要点を足す。
- 1日のまとめの中身が残っていない日や、あとから見出しが増えた日は、その日の見出しがそろってからまとめを作り直す。ドキュメントにまとめがあれば二重には書かず、見出しが増えた日だけ「1日のまとめ（あとから書き足した分）」として足す。
- 「これまでの記録」の「会話ごと」では、間が15分以内で、場所・相手・予定・テレビかどうかが同じ会話を1つのまとまりで見せる。画面の見え方だけで、記録とドキュメントは会話ごとのまま。

## こんなのあったけど、どう？
1日のまとめの「やること」を、「今日」タブに「こんなのあったけど、どう？」として出す（新しいものが届くと通知する）。Apple のリマインダーには書かない。

- **残す**: 考えたいものを「残しているもの」に置いておく。
- **消す**: いらなければすぐ消す。同じ文はもう出さない。
- 日付を押すと、その日の記録を見られる。
- 候補にするのは直近14日分だけ。判断は `suggestions.json` に端末ごとに持ち、iPhone と iPad では同期しない。

## テレビ・動画の見分け
会話を閉じて見出しを付けるときに、言語モデルが「実際の会話」か「テレビ番組・YouTube などの動画・ラジオや音楽」かを見分ける（ナレーション、出演者の掛け合い、CM、本人がほとんど話さない、などが手がかり。[自分] の発言の割合も渡す）。

- テレビ・動画なら、見出しが `20:00〜20:45　自宅　［テレビ］「番組名」　内容` の形になる（番組名・動画の題名は分かったときだけ）。
- その会話の名前の無い声（[人物N]）は `[テレビ]` `[動画]` に書き換え、覚えた声は忘れる（テレビの声が「人物N」として増えないように）。名前のある人と自分の発言はそのまま。
- テレビ・動画の会話は「会った人」や人物ノートに数えない。1日のまとめでは「テレビを流していた」として流れに入る。
- 番組を見ながら家族と話しているなど、実際の会話が中心なら会話として扱う。

### 行ごとの見分け

会話の中に混ざったテレビ・CM・ドラマのセリフ・動画・ラジオ、電車や駅・お店の放送も、行ごとに見分ける。
- 文字にするとき、iOS に入っている音の聞き分け（SoundAnalysis、端末内）で、行のあいだの背景の音（音楽・電車・拍手や笑い・テレビ）を調べて行に残す（低電力モードで充電していないときは調べない）。
- 会話が終わったら、名前の無い声と話者の無い行のうち、本人のまわりの会話ではない行を言語モデルに選んでもらう（背景の音も手がかりに渡す。迷ったら選ばない）。選ばれた行は話した人を [テレビ] [CM] [ドラマ・映画] [動画] [ラジオ・音楽] [放送] にし、話した相手には数えない。元の人は行に残す。自分・名前を付けた人・手で直した行は変えない。
- 見分け違いは、行を長押しして「話者を直す」で戻せる。

## ほかのアプリの音声を取り込む
「ほかのアプリの音声を取り込む」で、AUDAY などがドライブに保存した音声を取り込める。

1. ファイルアプリの「ドライブ」から、音声の入ったフォルダかファイルを選ぶ（Google ドライブのアプリが入っていてログインしていれば、ファイルアプリに出る）。
2. ファイル名の日時（`2026-10-15 09-30-12`、`20261015_093012`、`2026年10月15日 9時30分` など）を録音を始めた時刻として読む。読めなければ音声の情報やファイルの日付を使う。違っていたら一覧で直せる。
3. 5分ずつに分けて文字起こし待ちに入れ、その日付のドキュメントに書く（会話の見出し・1日のまとめも付く）。いまの録音を先に処理し、取り込んだ分は3つずつ進める。
4. 取り込んだものは覚えておき、もう一度選んでも外しておく。

Groq の無料枠は1日16時間分なので、たくさん取り込むと、その日の残りは端末内の文字起こしになる。

## 印を付ける
大事な話のときに印を付けると、その前後1分の行の頭に `★` が付き、1日のまとめ・週のまとめにも「★ 印を付けたところ」として出る。

- 時計: 録音中の画面の「★ 印」ボタン。指のダブルタップでも押せる。iPhone から離れていても、つながったときに届く。
- iPhone: 「今のところに印を付ける」。
- 行はその区切りが文字起こしされてから★が付く（ドキュメントの行も直す）。

## 録音が止まったら知らせる
「録音が止まったら知らせる」（初めはオン）にすると、

- 時計: 録音中は区切るたび（5分）に iPhone に知らせる。15分以上知らせが無ければ、iPhone に「時計の録音が届いていません」と通知する（時計の電池切れ・アプリが終わった・iPhone から離れているなど）。
- iPhone: 電話などで iPhone の録音が止まったら、画面を見ていなくても通知する。
- 時計の LifeLog が終わったときは、これまでどおり時計にも通知が出る。

## 記録を探す・記録に質問する
- 「記録を探す」: 言葉や名前で、これまでの行を探す（空白で区切ると、すべてを含む行）。押すとその日の記録が開き、音声も聞ける。
- 「記録に質問する」: 「先週田中さんと何を決めた？」のように聞くと、Groq の無料枠で答える。小さいモデルで質問から探す言葉・人・期間を取り出し、その期間の会話から関係の深いものを6,000文字まで集め、大きいモデルがその記録だけをもとに答える。根拠にした行も出る。期間を言わなければ直近60日から探す。

## 週のまとめ
月曜になると、先週（月〜日）の「週のまとめ」を `LifeLog/週のまとめ 2026-10-26〜2026-11-01` というドキュメントに書く（1週間の流れ・よく話した人・決まったこと・残っていそうなやること・話題・★）。その週の1日のまとめがそろってから作る。

## 画面の並び（2026-11-04 に整理）

- **今日**: 録音・印 → いまの様子 → **頼まれごと帳**（まだ・今日まで・確かめ待ちの数と、期限の近い3件）→ **AI からの質問**（まだ答えていないものがあるときだけ）→ **見直すもの**（今日の人物Nを整理・名前を付けてほしい声・声の見直し・聞き間違いかも。どれも無ければ出さない。テレビ・動画らしい声は数えない）→ こんなのあったけど、どう？ → 今日の会話 → 最近の発言。
- **記録**: 記録に質問する・話し方の振り返り → 日ごと（上の検索で言葉や名前を探す）。
- **人と場所**: 話した相手・自分の声 / 登録した場所 / 言葉の登録。
- **設定**: Google ドライブ / 同期 / Apple Watch / 文字起こし / 話者 / 会話のまとめ / 言語モデル / 音声（ドライブへの保存・周りの声と雑音・夜の聞き直し・取り込み）/ ほかのアプリとつなぐ（カレンダーなど・ショートカット）/ 点検と控え（自己点検・聞き取りの成績・登録の控え・記録の掃除）。

## 頼まれごと帳（2026-11-04）

「今日」の「頼まれごと帳」。仕事で頼まれたこと・引き受けたことを1か所にため、済むまで追いかける。中身は `tasks.json`（端末ごと・同期しない。新しいファイルなので、前からの保存形式は変えていない）。

- **会話から拾う**: 閉じた会話（直近3日・1回に3つまで）のうち、仕事の時間（職場にいた時間か平日の8〜19時）でほかの人の行がある会話と、★を付けた会話を、言語モデルで1回だけ見る（`taskScanned`）。本人が頼まれた・指示された・引き受けたことだけを、何を・頼んだ人・期限（言い方と日付）・根拠の発言・時刻で拾う。仕事の時間の会話は「職場の会話は端末内で」のとき外に送らない。拾ったものは「確かめ待ち」に入り、「入れる」「直して入れる」「違う」で決める（違うにしたものは、よく似たものも二度と出さない）。
- **★で確実に**: 頼まれた瞬間に時計の★を押すと、その前後2分で拾ったものは、はじめから帳に入る。★の近くで何も拾えなければ「★を付けたところ（時刻）」を確かめ待ちに出す（その場面の音声と前後1分の文つき）。
- **議事録の宿題**: 議事録を作ったとき、担当が自分か空の宿題を確かめ待ちに入れる。
- **書き足す・写真から**: 右上の＋から。写真（撮る・選ぶ）は iPhone の中（Vision）で文字を読み取り、言語モデルでやることを拾って確かめ待ちに（職場のメモかもしれないので、端末内で作る設定のときは外に送らない）。拾えなければ読み取った文字を1件にして出す。「こんなのあったけど、どう？」の「帳に入れる」でも入る。
- **追いかける**: 「まだ」は期限の近い順。○で済み（済みは30日出し、押すと戻る）。行を押すと直す（やること・頼んだ人・期限・メモ）。音声があれば「その場面を聞く」、会話からなら「記録を開く」。
- **知らせ**: 朝8時と18時（帳の画面で変えられる）に、まだの数・今日までと過ぎたものの数・確かめ待ちの数と、期限の近い3件を通知する。7日先まで iOS に頼んでおき、帳が変わるたびに頼み直す（iPhone だけ）。
- **写し**: iPhone は、帳が変わると（と日が変わると）ドライブの「頼まれごと帳」ドキュメント（読む用・まるごと書き直す）と、同期フォルダの「頼まれごと帳.json」（家の PC の `Build-AppRecords.py` が `archive/lifelog-app/頼まれごと帳.md` に写す。端末の同期では読まない名前）に書く。
- **人の画面の「これまでのやり取り」**: その人の声の行がある会話か、見出しの相手にその名前がある会話を、新しいものから30件（日時・場所・見出し・要点2つ）と、その人からの頼まれごと。押すとその日の記録を開く。

## AI からの質問とわかったこと帳（2026-11-05）

記録で AI が「合っているか分からない・あいまい」と思ったところを、本人に聞いて覚える。
- **いつ**: 夜（既定21時・質問の画面で変えられる）を過ぎた最初の処理で、その日の閉じた会話から**5つまで**作る（`Pipeline.makeQuestions`。1日ぶん1回、`askedDays`）。まだ聞いていない前の日も**7日前まで**、新しい日から処理のたびに1日ずつ作り（2026-11-05 本人の希望）、夜より前に作った分はその時刻に知らせる。質問の画面の「前の日の分も聞く」を押すと、その場で1日ぶん作る（知らせない）。まだ答えていない質問が10個（押したときは25個）あれば作らない。言語モデルが使えなければ次の機会にやり直す。職場の会話を含む日は「職場の会話は端末内で」に従う。
- **何を聞くか**: 何をしていたか・何の集まりか（`what`）／聞き間違いらしい言葉（`word`）／だれのことか（`who`）／決まったこと・やることが合っているか（`decision`）。渡すのは会話ごとの見出し・要点・文字起こしの頭（聞き取りが不確かな行には印）と、1日のまとめの「決まったこと」「やること」。もう聞いた質問は渡して、同じことは聞かない。プロンプトに見本の文は入れない。
- **答え方**: 「今日」の「AI からの質問」か「記録」の「AI からの質問・わかったこと帳」から。候補を押すか、書いて答える。「分からない」「的外れな質問」もある。▶︎でその場面を聞ける。答えたものは「答えたもの」から取り消せる。言葉の質問は、答えのあとで「『〇〇』→『△△』をこれからも直す」を押すと誤変換に登録する（押したときだけ）。
- **覚える**: 答えは `〔いつ・どこ〕質問（「対象」）→ 答え` の1行の「わかったこと」になり、`asks.json`（端末ごと・同期しない）に残る。次からの見出し・要点・1日のまとめ・頼まれごと探し・質問づくりで、**記録に手がかりの言葉が出てくるものだけ**（12個・1,500字まで）を「本人が教えてくれた確かな事実」として AI に渡す（`KnownFacts` / `Summarizer.known(for:)`）。文字を直す処理（誤変換直し・書き方そろえ）には渡さない。
- **作り直す**: 答えた会話は、見出しと要点（と、まとめを書いた日は1日のまとめ）を、わかったことを手がかりに作り直す（手で文字を直したときと同じ `resummarize`）。名前の付け替え・声のまとめは、答えても自動ではしない。
- **写す**: iPhone はドライブの「わかったこと帳」と、同期フォルダの「わかったこと帳.json」に写す。PC の `Build-AppRecords.py` が `archive/lifelog-app/わかったこと帳.md` を作る。わかったこと帳の画面で、左にずらして直す・消す。

## 聞き間違いかも

「今日」タブの「見直すもの」（見つかったときだけ）と「記録」の一番上の「聞き間違いかも」。自動の文字起こしで、音を聞き間違えて書いたと思われる言葉の一覧。

- 見つけ方: 直近14日の閉じた会話（テレビ・動画は除く）を、まだ読んでいないものから Groq の言語モデル（`openai/gpt-oss-120b`）に読んでもらい、同じ音・似た音の別の言葉、前後と意味がつながらない言葉、名前や専門用語の書き間違いを、理由と「たぶんこう」の書き方付きで出してもらう（話し言葉の崩れや言い間違いは出さない）。文字起こしのあと、多くても10分に1回、1回に8,000文字まで。「今すぐ探す」でも。登録した言葉・名前を付けた人・誤変換の直し先と、「合っている」にした言葉は出さない。手で直した行も出さない。同じ言葉は1つにまとめる。調べたものは `misheard.json` に残す（片付けたものは30日で捨てる）。
- 直し方: 「〇〇に直す（この N 行）」「直近30日の〇〇 N 行すべて」「別の書き方に直す…」「合っている（もう出さない）」。行を押すと音声が流れる。直すとアプリの記録とドキュメントの行が直り、「誤変換の一覧にも足す」（初めはオン）なら、これからの文字起こしでも自動で直る。
- まとめ直し: 手で文字を直した会話（「文字を直す」で直した行も）に印を付け、見出しと要点を作り直してドキュメントの見出しを置き換える。その日の1日のまとめがもう書いてあれば、それも作り直して置き換える（「あとから書き足した分」も含めて、先頭のまとめを消してから入れ直す。今日の分は日が変わってから）。一覧にその日の言葉が残っているあいだは待ち、片付いたら次の処理のときに作り直す。「まとめを作り直す」を押せばすぐ。人物ノートと週・月のまとめは作り直さない。

## 月のまとめ
月が変わると、先月の「月のまとめ」を `LifeLog/月のまとめ 2026-10` というドキュメントに書く。その月の1日のまとめがそろってから作る。
- 数字（記録のある日・会話の数・話していた時間）と「よく話した人」（名前を付けた人ごとの会話の数と日数、上位10人）は記録から数える。
- 「1か月の流れ」（週ごとに1行）・「決まったこと」・「やること（残っていそうなもの）」・「話題」は、日ごとのまとめを Groq の言語モデルにまとめてもらう（1日あたりの材料は 9,000 文字を日数で割った長さまで）。
- ★ 印を付けたところ（15個まで）。

## 記録の読み込み
日ごとの記録（`Application Support/days/日付.json`）は、読んだ中身を覚えておき、ファイルを書いた時刻が変わっていなければ読み直さない（人物ノート・1日のまとめの確認などが、5分の処理のたびに全部の日を読むため）。覚えるのはファイルの大きさで 48MB まで、超えたら長く使っていない日から忘れる。読み込みの回数と時間は「自己点検」に出る。

## 自己点検と診断
「設定」→「自己点検」。端末（低電力モード・空き容量・バックグラウンド更新）・許可（マイク・通知・位置・カレンダー・連絡先・移動）・設定・いまの状態（録音・時計・文字起こし待ち・同期・控え）・処理の重さ（1回の処理の時間、記録の読み込み）・時計の遅れ・人の数・最近のエラー（新しい50個を `diagnostics.json` に残す）を、✓／⚠ を付けて出す。
- 同じ中身を、ドライブの「LifeLog」の「診断」（iPad は「診断（iPad）」）に1時間に1回ほど書き直す（「ドライブの「診断」に書く」で今すぐも）。会話の中身・人の名前・メールアドレスは入れない。ドライブを読める AI に「診断を見て」と頼むと、実際の端末での動き具合を確かめられる。
- 「診断」を書いたときに、同期フォルダに「アプリの状態（端末の番号）.json」（端末・版・署名の期限・録音中か・文字起こし待ちの数・最後に処理した時刻。日時は ISO 8601）も書く（2026-11-05）。家の PC の `Watch-Freshness.ps1` が読み、署名が切れそうなときと、アプリの記録が長く届かないときに LINE で知らせる。名前に「-」が無いので、端末どうしの同期では読まない。

## 登録の控え
「設定」→「登録の控え」。覚えた声（名前の無い声・自動で覚えた声も）・まとめの記録（`merges.json`）・人ごとの言葉・こんなのあったけど・消した行・音声の置き場所の一覧と、設定（言葉の登録・場所を含む UserDefaults 全部）を、毎日1回控える。
- アプリの中（`Application Support/backups`、7日分）と、Wi-Fi のときはドライブの「LifeLog/控え」（`控え-端末-日付.json`、端末ごとに14日分。古いものはゴミ箱へ）。「今すぐ控える」はモバイル通信でも上げる。
- 会話の記録は同期でドライブの「同期」に渡っているので控えない。
- 控えを選んで「この控えに戻す」と、次にアプリを開いたとき、ほかのものが読む前に入れ替える（アプリを上にスワイプして終わらせてから開く）。入れ替えるのは登録のファイルと、設定のうち言葉の登録・場所・消したい言葉・カレンダーの選び方・聞き分けの厳しさだけ（端末の印や同期の進み具合は戻さない）。入れ替える前のものは `backups/戻す前-日時` に残す。ドライブの控えはほかの端末の分も選べるので、アプリを入れ直したときにも使える。

## iPhone の中の言語モデル

「設定」→「言語モデル」。見出し・要点・1日／週／月のまとめ・誤変換直し・聞き間違い探し・記録への質問・過ごし方・議事録を、Apple の iPhone の中の言語モデル（Foundation Models。Apple Intelligence に対応した機種で、Apple Intelligence がオンのとき）でも作る。無料で上限が無く、中身を外に送らない。

- 「使わない」「Groq が使えないときだけ」（初め。キーが無い・無料枠を使い切った・混んでいる・通信できないときの代わり）「職場の会話は端末内で」「いつも端末内で」。
- 「職場の会話は端末内で」は、職場にいた時間の会話（場所・職場のカレンダー・平日8〜19時で決める）と、それを含む1日・週・月のまとめ、職場の会話が入る質問を、Groq に送らない（端末内で作れなかったら、作らずに次の機会にやり直す）。
- 端末内のモデルは一度に読める量が少ない（入れる文と答えで4,096トークン）ので、長い会話は1,200文字ずつ要点メモにしてからまとめ、それでも長い文は頭（指示）と終わりを残して途中を省く。答えの JSON が読めなければ1回だけ頼み直す。
- 呼び出しはすべて `Summarizer.chat` を通り、端末内か Groq かをそこで決める（職場の会話かどうかは、呼ぶ側が `Summarizer.sensitive` で伝える）。

## 話し方の振り返り

「記録」→「話し方の振り返り」（2026-11-04 に「人と場所」から移した）。記録の自分の行から、iPhone の中で数える（無料）。
- 話す割合（会話の文字のうち自分の分）・速さ（自分が話していた時間＝次の行までの間、1行20秒まで、あたりの文字数）・口ぐせ（えー・えっと・あのー・なんか・まあ・うーん など、千字あたり）・質問（「？」や「ですか」「かな」で終わる自分の文、会話1つあたり）・心拍が上がっていた会話の数（ヘルスケアが使えるとき）。
- 直近7日とその前（7週）、職場と職場以外、名前を付けた相手ごと、週ごと。テレビ・動画の会話は数えない。
- 「ひとことで振り返る」で、数字だけ（会話の中身は渡さない）を言語モデルに渡し、良かったところ・気をつけるとよいところ・次に試すことを返してもらう。
- 「会う前のおさらい」に、前回その人との会話で自分が話した割合を添える。
- 文字起こしは口ぐせを書かないことがあるので、口ぐせの数は目安。

## 議事録

日ごとの記録の右上の「議事録」（書類の印）。会話を選んで「議事録を作る」、または自動で。
- 自動で作るのは、15分以上・1,500文字以上の会話で、職場のカレンダーの予定と重なるもの、職場にいた時間で参加者のいる予定と重なるもの、職場にいた時間で自分のほかに2人以上の声があるもの（職場のカレンダーを iPhone に入れられなくても、「場所」で会社を職場にしておけば見分ける）。アプリを開いているか充電中のときに、直近7日から1つずつ。「職場の予定の会話は自動で作る」（初めはオン）で止められる。
- ドライブの「LifeLog」に「議事録 2026-11-04 1400 予定名」を作り、日時・場所・出席者（声で分かった人と予定の参加者）・目的・議題ごとの要点（話した人が分かれば［名前］）・決まったこと・宿題（担当・期限）・次回を書く。長い会議は区切りごとに要点メモにしてからまとめる。
- 職場の会議は「職場の会話は端末内で」なら iPhone の中で作る。

## 記録の検索

「記録を探す」と「記録に質問する」は、iPhone の中の索引（`Application Support/search.sqlite`、SQLite の全文検索）を使う。日ごとの記録のファイルが書き換わった日だけ、文字起こしのあとに入れ直す（記録から作る写しなので、消えても作り直せる）。
- 日本語は言葉の区切りが無いので、文を2文字ずつの組にして入れ、探す言葉も同じ組の並びとして探す。2文字以上の言葉は何か月分からでもすぐ見つかる。1文字の言葉だけのときは、今までどおり全部の記録を見る。
- 「記録に質問する」で期間を言わなかったときは、直近60日に加えて、言い換えを含む言葉が索引で見つかった前の日も探す。

## ヘルスケア

「設定」→「カレンダー・連絡先・移動・睡眠」→「ヘルスケア」。Apple Watch の睡眠・心拍・安静時心拍・歩数を読む（書かない）。
- 寝ているかを睡眠の記録で見分ける（記録が無い時間は、今までどおり iPhone が止まっていたかで推し量る）。
- 会話を閉じるとき、そのあいだの心拍の平均と最大を残し、直近7日の安静時心拍より平均で20以上か最大で30以上高ければ「心拍が上がっていた」とする。記録の見出しに ♥︎最大値、1日のまとめに「心拍が上がっていた会話」。
- 1日のまとめに「体調: 睡眠 ◯時間◯分・歩数 ◯歩」（前の日の18時からその日の12時までの睡眠と、その日の歩数）。
- 署名にヘルスケアの許可（`LifeLog/LifeLog.entitlements`）が要る。CI は App Store Connect の Secrets があるとき、ビルドの段階から署名して TestFlight に上げる（そのときだけ使える）。署名なしの IPA を Sideloadly で入れたときは、許可を聞くと「使えない」と出る。

## 自動テスト
`.github/workflows/tests.yml` が、iPhone のシミュレーターで `LifeLogTests` を動かす（`project-tests.yml` は project.yml にテストの部品を足したもの）。端末間の同期の合わせ方（新しい版を残す・消した会話を戻さない）、消す行の見つけ方、名前の取り出し、騒がしさの判定などを確かめる。IPA を作る「TestFlight」とは別に動くので、テストが失敗しても IPA は作られる。テストのときはアプリの画面と裏の処理を動かさない。

## これまでの記録と聞き直し
アプリの「これまでの記録」で、文字起こしを日ごとに見られる（会話のまとめを入れた版より後の分）。日の画面の上で「過ごし方」と「会話ごと」を切り替える。

### 過ごし方
1日を「何をしていたか」の長い塊で、時刻順に並べる。塊を押すと、その中の会話（行・再生・手直し）を見られる。

```
12:00〜16:00  4時間            会話 23
ダンスの練習
スタジオ　田中さん、佐藤さんと　〔ダンス〕
・新しい振り付けを通しで確認
・発表会の曲順が決まった
```

- 閉じた会話（見出しと要点）とその日のカレンダーの予定を Groq（`openai/gpt-oss-120b`、枠が無ければ `20b`）に渡し、同じ用事・同じ場所の会話を、途中の短い休憩や電話もまとめて1つの塊にする（目安は1日3〜10個）。もう1回の呼び出しで、塊ごとに「その中でしたこと」を1〜4行にする。
- 塊と時間が重なるカレンダーの予定は名前を添え、予定の始まり・終わりが45分以内なら、塊の時刻を予定に合わせる（12:08〜15:47 の会話 → 12:00〜16:00）。
- 録音の無い時間のカレンダーの予定は「予定・録音なし」、15分以上の移動（Core Motion）は「電車・車で移動」などとして間に入る。
- 作った塊は `Application Support/activities/日付.json` に、会話の記録とは別に保存する。会話・予定が変わったときだけ、日の画面を開いたときに作り直す（下に引っぱると、いつでも作り直す）。Groq のキーが無いときや混んでいるときは、30分以上の途切れ・場所や予定の変わり目で区切る（次に開いたときに言語モデルでやり直す）。
- ドキュメントの「1日のまとめ」の「1日の流れ」も、この塊で書く。
- まだ閉じていない会話は「まだまとめていない会話」として一番下に出る。

### 会話ごと

- 行を押すと、その行の1秒手前から再生する。もう一度押すと止まる。
- 行を長押し（または右にスワイプ）すると、話者を直せる（「登録と手直し」）。
- 時計の音から書いた行には時計の印、印を付けた行には★が付く。
- 「音声をドライブにも保存」（初めはオン）にすると、文字起こしが終わった音声を Wi-Fi のときだけドライブの `LifeLog/音声/日付/` に上げる。自動では消さない。
- iPhone の中の音声は26時間たったら消す（まだ上げていない分は上げ終わるまで残す）。消えた分は、行を押すとドライブから取ってきて流す。
- 保存をオフにすると、26時間を過ぎた音声は消え、文字だけが残る。

## 人物ノート
名前を付けた相手ごとに、ドライブの「LifeLog」フォルダに「人物ノート - 名前」というドキュメントを作り、その人と話した会話を新しい順に書き足す。

```
10/30(木) 14:05〜14:40　会社　来週の提案資料の打ち合わせ   ← 見出し3
一緒にいた人: 佐藤さん
・提案は A 案で進める
・資料は木曜までに自分が作る
（2026-10-30 のドキュメント）
```

- 要点は会話の見出しと同じもの。要約が無いときは、その人の発言を3つまで載せる。
- 「人物3」のように名前を付けていない人は書かない。名前を付けたあとに話した会話から書き足される。

## 場所
「場所を記録する」をオンにすると、大きく移動したとき（数百 m）だけ位置を記録し、見出しに場所を添える。

- 「登録した場所」で今いる場所に名前（自宅・会社など）を付けると、その300 m 以内はその名前で出る。
- 場所ごとのスイッチで「職場」を決める（「会社」「職場」「オフィス」「事務所」を含む名前は最初からオン）。話者の聞き分けで、職場の人と職場以外の人を分けて照らし合わせるのに使う。
- それ以外は、近くの駅があれば「〇〇駅近く」、無ければ「〇〇付近」。
- 画面を閉じているあいだも記録するには、位置情報の許可を「常に」にする。位置はこの iPhone の中だけに置く（地名を調べるときだけ Apple に問い合わせる）。

## 画面のタブ

- 今日: 録音・印・いまの様子・今日の会話・最近の発言
- ライブ: リアルタイム文字起こし
- 記録: 日ごとの記録、言葉や名前で探す、記録に質問する
- 人と場所: 話した相手・自分の声・場所・言葉の登録
- 設定: Google・時計・文字起こし・話者・まとめ・音声の保存と取り込み・記録の掃除

## ライブ文字起こし

「ライブ」タブでオンにしている間だけ、iPhone のマイクの声を話の切れ目（または12秒）ごとに Groq の whisper-large-v3-turbo に送り、返ってきた文を流す。声の無い区間は送らない。画面に出すだけで、記録はいつもの5分ごとの文字起こしで書く。時計だけで録っているときは、オンの間 iPhone でも録る。アプリを閉じて10分たつと自動でオフ。iPhone の録音は AVAudioEngine で受け、同じ音をファイルとライブの両方に渡す。

## 記録の掃除

「設定」→「記録の掃除」で、全期間から次の行を探し、確かめてから消す（アプリとドキュメントの両方から行ごと。消した行は30日間「消した行」から戻せる）。

- 決まり文句（ご清聴ありがとうございました、チャンネル登録など）
- 同じ文の連打（記号を除いて5〜40文字の同じ文が、間に1行まで挟んで5分以内に3回以上続く。区切りをまたいでも数える）
- 壊れた行（「3行目の直した文」など）
- 自分で足した「消したい言葉」だけの行

書いたすぐあとにも同じ見つけ方で自動で消す。掃除の画面で外した行と戻した行は、自動でも消さない。前に中身だけ消して残った空の段落も一度だけ詰める。

## 言葉の登録

「人と場所」→「言葉の登録」で「いつも」「職場だけ」「職場以外だけ」に分けて登録する。職場にした場所では いつも＋職場、ほかの登録した場所では いつも＋職場以外、場所が分からないときは平日8〜19時を職場とみなす。名前を付けた人の名前も、その人の場の言葉に入る。クラウドの文字起こしのヒント、端末内の文字起こしのヒント、誤変換を直す言語モデルに渡す。「よく間違えられる書き方 → 正しい書き方」は文字起こしのあとにそのまま置き換える。記録の行を長押しして「言葉を登録」からも足せる。

## 言っていない文を書かない

Whisper は日本語と決めて渡すと、小さな雑音・寝息・外国語の動画などにも、もっともらしい日本語の文を作ってしまう。そこでクラウドの行を、同じ時間（前後5秒）の端末内の文字起こしと読み（ローマ字）で比べ、読みの3文字の並びが25%以上重ならない行は捨てる。端末内で何も聞こえていない区切りは、そもそもクラウドに送らない。

## iPhone 内の Haas-ja

[Haas-ja-v1.0](https://huggingface.co/third-intelligence/Haas-ja-v1.0)（Third Intelligence、Apache-2.0）の Core ML 版 [Sanami/haas-ja-coreml](https://huggingface.co/Sanami/haas-ja-coreml)（非公式の変換、Apache-2.0）を使う。Swift の部品（HaasCore）と frontend.bin・vocab.json は CI が版を固定して取ってくる（Vendor/HaasCore、LifeLog/Haas）。モデル本体（約620MB）は「設定」→「iPhone 内の Haas-ja」から初回にダウンロードし、iPhone 上で変換して Application Support/haas に置く（バックアップ対象外）。

オンのあいだは、端末内の文字起こし（SpeechAnalyzer）が声を聞き取った区間を、間が1秒未満なら14秒まで1つにまとめ、その区間ごとに Haas-ja で文字にする（1区間＝1行）。動かせなかった区切りは、いつもの方法（Groq など）で文字にする。

## 家の PC の Haas-ja

家の Windows PC で `pc/lifelog_pc.py`（LifeLog PC）を動かし、iPhone から区切りを送って Haas-ja で文字にしてもらう。モデルは [Haas-ja-v1.0](https://huggingface.co/third-intelligence/Haas-ja-v1.0) の ONNX 版 [oboroge0/Haas-ja-v1.0-onnx](https://huggingface.co/oboroge0/Haas-ja-v1.0-onnx)（非公式の変換、Apache-2.0）を sherpa-onnx で CPU で動かす（初回に約2.4GB を取ってくる）。

- PC 用の実行ファイルは CI（`.github/workflows/pc.yml`）が Windows で作り、成果物 `LifeLogPC` に置く。使い方は `pc/README.txt`。
- 送るのは声のあった区切り（AAC、約1.2MB）と、端末内の文字起こしで声があった区間。合言葉（Bearer）が合わない相手には返さない。
- 外からは Tailscale の住所（100.…）で届く。モバイル通信で送るかは設定で選べる。
- 順番は 家の PC → iPhone 内の Haas-ja → クラウドの高精度 → 端末内。PC に届かなかったら2分間は試さない。

## 人物Nの整理と、自分の声をまとめる

- 「今日」の「見直すもの」の「今日の人物Nを整理」（日ごとの記録の右上からも）で、その日に出てきた名前の無い声を、「名前の候補」（声の近い人・呼ばれた名前・予定の参加者。上の「声だけで誰か分からないとき」と同じ）から1回でまとめたり名前を付けたりできる。「この声が話したことを見る」で、ほかの日の会話も確かめられる。ほかの人を選ぶ・新しく名前を付けることもできる。記録とドキュメントの名前も直る。
- 「話した相手」の「自分をまとめる」で、自分の声だった人を選んでまとめて「自分」にする（1人ずつなら、その人の画面の「自分の声だった」）。

## まとめた人を分け直す

人の画面（「人と場所」→「話した相手」→ その人。自分にまとめたときは一番上の「自分」）の「まとめた人を分け直す」。
- まとめるとき（手でも、会話が終わったときの自動のまとめでも）、まとめる前の人（名前・声）と書き換えた行の時刻を `merges.json` に残す。「「人物123」を戻す」で、声ごと元の人に戻し、行の名前も戻す。
- 記録を残す前のまとめは「ドキュメントの履歴から探す」。いまその人になっている行のうち、ドライブの日ごとのドキュメントの前の版（版の履歴、1日40版まで）で「[人物N]」だった行を番号ごとに集めて見せる。選んだものを「人物N」に戻し、その行の声を録音から5つまで覚え直す。まとめた先の、自動で覚えた声のうち戻した人の声に近いものは移す（登録・手直しの声と名前は動かさない）。

## 話題ごとの言葉

言葉の登録の「話題ごとの言葉」。話題ごとに専門用語と合図の言葉を登録すると、そのどれかが聞こえてから30分は、専門用語を Whisper・端末内のヒントと誤変換直しの言語モデルに渡す（Whisper のヒントの先頭に置く）。話題は端末内の文で見つけ、精度の高い文でも見つけ直して直しに使う。

## 周りの声と雑音

- 設定 →「周りの声と雑音」。自分の声の大きさを機器ごとに覚え、それより14dB以上小さい声と、名前の無い声で前後3分に自分が話していないものを書かない（既定は職場にいるときだけ）。外した行は「消した行」（種類「周りの声」）に残る。
- **2026-11-05 に直した**: ①「職場にいるときだけ」は、登録した職場にいるときと職場のカレンダーの予定の最中だけ（平日8〜19時という時刻の推定では使わない。祝日の夕方の食事で友だちの声を外していた）。②名前を付けた人の声は、自分の声より小さくても外さない（1対1の相手の声が14dB以上小さく入って外れていた）。直す前に外した行のうち、新しい決まりなら残っていた行は、「周りの声と雑音」の「外しすぎた行をまとめて戻す」で件数を見てから戻せる（1行ずつドキュメントに入れ、戻した会話は見出しと要点を作り直す）。
- 聞き直すときだけ、スペクトル減算（`Denoiser`）で定常的な雑音を減らし、大きさをそろえて鳴らす。録音は変えない。
- 騒がしい所（`NoiseMeter`）: 区切りごとに 50ms ごとの大きさから「周りの音の底」（静かなほうから2割）と「声の大きさ」（VAD の区間の大きいほうから1割）を出し、底が -42 dBFS 以上か、底が -55 dBFS 以上で声との差が 12 dB 未満なら騒がしいとみなす（しきい値はまだ実際の録音で合わせていない）。騒がしい区切りでは:
  - Haas-ja で書いたあと、クラウドの Whisper でも聞き、Haas-ja が文を書かなかった声の区間の行を補う（設定「騒がしい所はクラウドでも聞いて補う」、既定オン。「高精度で文字起こし」がオンのときだけ）。
  - クラウドの行が端末内の聞き取りと合わなくても、声のある区間なら残す（確からしさが低い「？」の行になる）。
  - 行に `noisy` を付け、記録では時刻の下にスピーカーの印を出す。
- クラウドの行で、端末内と合わない・声の無いところの行は、捨てずに「消した行」（種類「端末内と合わなかった文」）に回す。
- 雑音を消してから文字起こしすることはしていない。スペクトル減算などの雑音除去は、Whisper 系の文字起こしではかえって間違いを増やすことが多いため（聞き直すときの雑音を減らす処理だけ）。

## 記録に出さない人

人の画面の「この人の声を記録に出さない」。声で見分けて、その人の行は記録にもドキュメントにも書かず、「消した行」（種類「記録に出さない人」）に30日残す。「これまでの行も記録から消す」で、過去の行も同じように消せる（戻せる）。記録に出さない人は、2週間聞かなくても忘れず、ほかの声とも自動でまとめない。同期でほかの端末にも伝わる。

## 話した場所

人の一覧・人の画面・名前の無い声の整理・話者を直すときの人の選び方に、その声が出てきた会話の場所（会話の見出しの場所、多い順）を出す。人の画面では、声のひとこまごとの場所も出す。場所は「場所を記録する」がオンのときの会話だけ。

## 会う前のおさらい

「設定」→「カレンダー・連絡先・移動・睡眠」の「会う前のおさらいを通知する」（初めはオン。カレンダーを使うときだけ）。

- カレンダーの予定（終日・12時間より長い予定は除く）の10分前に、その予定で会う名前を付けた人と、前回話した会話の日付・見出し・要点（3つまで）を通知する。
- 会う人は、予定の参加者の名前か、予定名に入っている名前（「田中さんと面談」）で決める（空白・「さん」などを除いて比べる）。前に話した閉じた会話が無い人は出さない。テレビ・動画の会話は使わない。
- 先の24時間の予定（10個まで）を iOS に頼んでおくので、アプリが閉じていても時刻に出る。アプリを開いたときと文字起こしのあと（多くても10分に1回）に頼み直す。iPad では出さない（二重にならないように）。
- 通知はロック画面にも出る。

## 聞き取りの成績

「設定」→「聞き取りの成績」（「周りの声と雑音」からも）。どこで・どの機器で聞き取りが悪いかを数字で見る。記録には影響しない。

- 機器ごと（iPhone・時計）と場所ごと（多い順に10か所）に、直近14日の行の数と、「？」（確からしさが低かった行。あとで直した行も含む）・手で直した行・騒がしい所で聞き取った行の割合。
- 周りの音: 文字にした区切りごとに、周りの音の底と声との差を `noise-log.json` に残し（直近2,000個）、機器ごと・場所ごとの真ん中の値と、騒がしいとみなした割合を出す。騒がしさのしきい値（-42 dB など）を実際の録音で合わせるため。

## カレンダー・連絡先・移動・睡眠

- カレンダー（EventKit）: 過ごし方の区切りと名前、会話の見出しに〔予定名〕、要約に予定・場所・参加者、聞き取りのヒントに予定名・場所・参加者。職場のカレンダーを選ぶと、その予定の時間は職場。使わないカレンダー（家族の共有など）はスイッチで外せる。
  - Google カレンダーは、iPhone の「設定」→「アプリ」→「カレンダー」→「カレンダーアカウント」→「アカウントを追加」→「Google」でアカウントを足すと、ほかのカレンダーと同じように読める。アプリに Google Calendar API を足す必要はない。
- 連絡先（Contacts）: 会話で「さいとうさん」「斉藤くん」「田中部長」のように呼ばれた名前の読み（ローマ字。長音はそろえる）が、連絡先の姓・名・ニックネームの読み（ふりがな、無ければ書き方から推し量る）と同じなら、連絡先の書き方を聞き取り（Whisper のヒントの先頭）と誤変換直しの「この表記に寄せる」言葉に足す。夜の聞き直しのヒントにも入れる。外に渡るのは読みが合った名前だけ。
- 移動の様子（Core Motion）: 見出しに「（歩きながら）」「（電車・車で）」。
- 睡眠: 寝る時間帯に iPhone がほとんど止まっていれば寝ているとみなし、端末内の文字起こしだけにして、短い文と小さな声を書かない（種類「寝ているあいだ」）。ヘルスケアは署名に HealthKit の権限が要り、Sideloadly の署名なしの IPA では使えないので使わない。
- ライブ文字起こしは iPhone 内の Haas-ja（モデルが無ければ Groq）。補正はかけない（速さ優先）。

## 聞き取りの精度を上げるしくみ

- **区切りの切れ目**: 5分たったあと、声が途切れた瞬間（最大20秒待つ）で区切るので、言葉が2つの区切りに分かれて崩れません。
- **2つの聞き取りの見比べ**: Haas-ja（またはクラウド）と iPhone 標準の聞き取りの読みが大きく食い違う行は、言語モデルに両方を見比べてもらいます。合い方は行ごとの「確からしさ」として残し、低い行は記録の画面で薄く「？」付きで出ます。
- **時計と iPhone の選び方**: 発言ごとに聞き取りの良いほうを選びます。片方でしか聞き取れていない発言も残します。
- **声の大きさで自分を見分ける**: 覚えた自分の声の大きさに近い声は「自分」と決めやすく、ずっと小さい声は「自分」にしにくくします。
- **会話ごとのまとめ直し**: 会話が終わると、同じ人が別の「人物N」に分かれていないか見て、まとめます（名前の無い声だけ。名前を付けた人どうしはまとめません）。
- **呼ばれた名前**: 「人物Nを整理」と名前の無い声の画面で、「〇〇さん」と呼ばれたすぐあとに話していた声に、その名前を候補として出します（全期間から数えます）。
- **文字を直す**: 記録の行を長押し（または右へスワイプ）→「文字を直す」。直したところを誤変換の一覧に足すかを、その場で選べます。
- **声のある部分だけを文字にする**: 端末内の声の見分け（FluidAudio の Silero VAD）で声のある区間を探し、Haas-ja はその区間だけ（端末内の文字起こしの区間と合わせて）文字にします。声が0.5秒もない区切りは、重い聞き取りと言語モデルの直しを動かしません。クラウドの行で、声のある区間（前後1.5秒）から外れたものは捨てます。
- **会話の中で書き方をそろえる**: 会話が終わると、同じ名前や言葉が行によって違う字で書かれていないかを言語モデルに見てもらい、読みが同じで、そろえる先が会話の中か登録した言葉にあるものだけ置き換えます。手で直した行は変えず、直す前の文字も残します。
- **人ごとの言葉**: 名前を付けた人と話した会話によく出て、ほかではあまり出ない言葉を数え（`wordstats.json`。人や言葉の登録とは別のファイル）、その人の声が聞こえているあいだ聞き取りと直しのヒントにします。
- **言葉の登録の候補**: 何日にもわたって出てくる固有名詞らしい言葉と、手で直した言葉を「言葉の登録」の「登録の候補」に出します。登録されるのは押したときだけです。左へスワイプで候補から外せます。
- **夜の聞き直し**: 夜（22〜6時）に充電しているとき、手元の1日分の音声を、その日に出た名前・話題・予定をヒントに聞き直し、前より良くなった行だけ差し替えます（設定 →「夜の聞き直し」で今すぐも可）。手で直した行は変えません。

## 電池

- 時計の録音は 16kHz・1ch で保存します（文字起こしは元々この細かさで聞くので、精度は変わりません）。
- 待機モードは、時計が録音しているあいだだけ動きます。
- iPhone が低電力モードで充電していないときは、iPhone の Haas-ja を動かさず家の PC かクラウドに回します（夜の聞き直しで取り戻します）。時計が低電力モードのときは、3つ（15分ほど）溜まってからまとめて iPhone に送ります。
- **音がしないあいだは書かない**（設定 → Apple Watch、既定はオン）: iPhone と時計で、1分続けて静かなら区切りを閉じて休み、音がしたらその1秒前から書き始めます。区切りの名前は書き始めた時刻なので、行の時刻はずれません。無音の区切りを作らず、送らず、文字にもしないぶん電池と通信が減ります。時計は休んでいるあいだも5分ごとに iPhone に知らせ、iPhone は休んでいる時計の区切りを待ちません。
- 時計の画面に、iPhone とのつながりと、送れていない録音の数が出ます。4つ以上溜まると時計に通知が来ます。

## ドライブを読む AI のための案内

ChatGPT や Claude に Google ドライブの LifeLog フォルダを読ませるときのために、フォルダに2つのドキュメントを置き、中身が変わったら（多くても20分に1回）書き直します。日ごとのドキュメントには触りません。

- 「00 はじめに読んでください（AI 向けの説明）」: フォルダの中身、日ごとのドキュメントと行の形（[自分]・[人物N]・★ など）、聞き間違いがあること、答えるときのコツ。名前を付けた人（職場か、よく話す言葉）と、登録した言葉・話題の言葉・よくある聞き間違いも載せます。
- 「01 日ごとの索引」: 日ごとの過ごし方（何時から何時まで何をしていたか）・会った人・場所・決まったこと・やること・会話の数。新しい日が上。

## 家の近くでは録音を休む（家の iPad が録音するとき用）

「人と場所」→「場所」で、登録した場所を長押しして「ここでは録音を休む」を選ぶ。その場所の範囲（既定 300 m）にいるあいだ、iPhone と時計は、マイクは聞き続けたまま、録音ファイルに書くのだけを休む（音がしても書かない）。離れて位置が変わると自動で書き始める。マイクを握ったままなので、iOS が裏からの録音開始を許さなくても、書き始めを待たされない。位置は「大きく移動したとき」だけ受け取るので、着く・離れるの検知には数分かかることがある。位置情報が使えない・位置が36時間以上古いときは休まない（書き落とさないため）。時計には iPhone から applicationContext で伝わる。休んでいる間は「今日」の「いまの様子」に表示する。

## ほかの場所から使う

- コントロールセンター・ロック画面の下のボタン・アクションボタンに「録音を始める・止める」「印を付ける」を置けます。
  - 「録音を始める・止める」は `AudioRecordingIntent`。LifeLog を開かず、ロックしたまま（`authenticationPolicy = .alwaysAllowed`）で動く。iOS の決まりで、こうして始めた録音のあいだは Live Activity（ロック画面と Dynamic Island の「LifeLog 録音中」、止めるボタン付き）を出す。Live Activity は8時間で iOS に終わらせられるので、録音中にアプリを開くと4時間より古ければ出し直す。
  - 「印を付ける」は押すと LifeLog が開いて動く。
- ショートカット App の自動化に使える操作：「録音を始める（録音中なら何もしない）」「録音を止める（録音中でなければ何もしない）」「LifeLog を開いて録音を始める」。始めるのを iOS の決まりでアプリを開かずにやると、バックグラウンドからは始められないことがある（フォアグラウンドから始めた録音を、あとから止めるのは問題ない）。確実に始めたいときは「開いて録音を始める」を使う。
- iPad にも入る（iPhone と同じ IPA）。時計・歩数（Core Motion）は iPad では使えない。記録と登録は下の「iPhone と iPad の同期」で合わせる。2台が同じ日のドキュメントに交代で書いても見出しの位置がずれないよう、見出しは会話の最初の行を探して差し込む。
- 時計の文字盤に LifeLog を開くボタン（コンプリケーション）を置けます。
- Sideloadly でこれらのボタン（拡張機能）を入れられなかったときは、同じ成果物の `LifeLog-unsigned-no-widgets.ipa` を使ってください（ボタン以外は同じです）。

## iPhone と iPad の同期

「設定」→「iPhone と iPad の同期」（既定でオン）。同じ Google アカウントでログインした端末どうしで、記録（会話と行）・話した相手（名前・場・登録や手直しで覚えた声）・言葉の登録（言葉・直し・話題）・登録した場所を、ドライブの「LifeLog/同期」フォルダを通して合わせる。アプリを開いたときと、文字起こしのあと（多くても3分に1回）に動き、「今すぐ合わせる」でも動く。

- 端末ごとに自分のファイル（`vocabulary-<端末>.json`、`people-<端末>.json`、`day-YYYY-MM-DD-<端末>.json` など）だけを書き、ほかの端末のファイルを読んで合わせる。同じファイルを2台で書き合わないので、片方の書き込みが消えない。
- 記録は会話ごとに番号（`rev`。中身が変わるたびに増える）を持ち、大きいほうを残す。同じ番号で中身が違えば、どちらの端末でも同じほうを選ぶ。消した会話は「消した印」で伝える。続いている（まだ閉じていない）会話は渡さない。
- 言葉・直し・話題・場所は、登録と削除の時刻を別に覚えておき、後からしたほうを残す（同期より前からある登録は、ずっと前に登録したものとみなす）。登録の保存の形は変えていない。
- 人は同じ番号どうしを合わせる。名前と場は後から変えたほうを残し、登録・手直しで覚えた声は両方を足す。自動で覚えた声は端末ごとのマイクに合わせたものなので渡さない。消した人は、そのあとこちらで聞いたり直したりしていなければ消す。自分は消さない。人を勝手にまとめたり名前を変えたりはしない。
- 番号がぶつからないよう、iPad は新しい人に 100000 からの番号を付ける。iPad で初めて同期する前に、iPad で付けた番号を一度だけ 100000 からの番号に付け替える（記録の行とドキュメントの名前も直す）。
- 「ここでは録音を休む」は端末ごとのまま（家の場所が iPad に届いても、iPad は家で録音を休まない）。
- 音声は、ほかの端末が上げた分の一覧も受け取り、どちらの端末からでも聞き直せる。
- 1日のまとめ・人物ノート・週のまとめ・AI 向けの案内と索引は、iPhone だけが書く（iPad の会話も同期で届くので、両方の分をまとめて書く）。
- 初めて同期する前に、記録・人・言葉・場所をアプリの中（`Application Support/sync-backup-日時`）に一度だけ控える。控えを取れなければ同期しない。
